# Tasker — техническая спецификация (вариант Б: ядро на Go)

> Локальный markdown-редактор заметок и задач для macOS. Одиночный пользователь, без облака, без аккаунтов.
> Название — **Tasker**. В исходной редакции спеки оно было рабочим («Oak») и заменено 2026-08-19.

Версия документа: 1.0 · Целевая платформа: macOS 13+ (Apple Silicon)
**Вариант Б выбран и реализуется. См. `VARIANT.md` про его слабые места.**

---

## 1. Зачем это существует

Три вещи, которых нет ни в одном бесплатном аналоге одновременно:

1. **Редактор, в котором приятно печатать.** CodeMirror 6 с подсветкой markdown прямо в тексте и настоящим vim-режимом.
2. **Заметка = задача.** Статус (`active` / `onHold` / `completed` / `dropped`), закрепление, теги. Завершённые уходят из списка сами.
3. **Агент — полноправный клиент.** Claude Code во время работы над кодом может завести заметку, дописать в существующую, поменять статус, найти нужное. Это не «AI-фича внутри приложения», а MCP-сервер поверх того же хранилища.

Сценарий, ради которого всё затевается:

> Работаю с Claude Code над задачей A. Находим баг, который к A не относится. Говорю: «заведи задачу, вернёмся после текущей». Агент создаёт заметку со статусом `active`, тегом репозитория, ссылкой на текущую заметку и описанием бага. Я её вижу в приложении сразу — без перезапуска, без импорта.

## 2. Принципы, от которых нельзя отступать

| Принцип | Следствие |
| --- | --- |
| **Файлы — источник правды** | Заметка — `.md` файл с YAML frontmatter. SQLite — только индекс, сносится и перестраивается без потери данных. |
| **Вся логика — в Go** | Фронтенд не содержит бизнес-логики. Он рисует и вызывает биндинги. Ни парсинга frontmatter, ни построения запросов, ни работы с файлами на стороне JS. |
| **Никакой системы плагинов** | Приложение для одного человека. Нужна фича — правится исходник. |
| **Никакого AI внутри приложения** | Ни автокомплита, ни ассистента, ни API-ключей. Весь интеллект снаружи, через MCP. |
| **Vim — база, а не опция** | Включён по умолчанию, тестируется наравне с обычным вводом. Выключатель есть, но он для второго человека, а не для выбора «как настроить». |
| **История — это git, и она по желанию** | Никаких ревизий в базе. Хранилище по умолчанию — просто папка с `.md`; включённая история превращает её в git-репозиторий с автокоммитом. |
| **Приложение может быть закрыто** | MCP — отдельный бинарник поверх того же пакета, UI ему не нужен. |

Для приложения это неверно — Wails на macOS привязан к Cocoa и с `CGO_ENABLED=0` не собирается вовсе, проверено. Выгода тем не менее реальная и осталась: `tasker-mcp` и `tasker-scan` собираются без cgo и остаются самодостаточными бинарниками, внешнюю библиотеку SQLite не надо ни вендорить, ни линковать, а FTS5 работает без build-тега. |

`internal/vault`, `internal/index`, `internal/watcher`, `internal/gitstore`, `internal/notes` **не импортируют Wails**. Проверяется линтером. Это позволяет и тестировать их обычным `go test`, и переиспользовать в `tasker-mcp` без изменений. `internal/notes` появился по ходу фазы 2: «создать заметку» — это файл, строка индекса и коммит вместе, и та же связка нужна и приложению, и MCP-серверу. В `internal/app` её положить нельзя — там Wails, а MCP обязан оставаться бинарником без него.

## 4. Хранилище на диске

### 4.1. Раскладка

```
~/Notes/                          # vault, путь настраивается
├── .git/
├── .tasker/
│   ├── index.sqlite               # индекс, в .gitignore
│   ├── notebooks.json             # иконки и порядок ноутбуков
│   └── config.json
├── .gitignore
├── attachments/2026/08/rr3k9q2x.png
├── templates/bug-report.md
├── .trash/
├── Работа/
│   ├── Проект X/refactoring-plan.md
│   └── standup-notes.md
└── Личное/pokupki.md
```

- **Ноутбук = папка**, вложенность произвольная. Список ноутбуков строится обходом каталогов, а не из путей заметок: пустая папка — тоже ноутбук, и без обхода только что созданный ноутбук был бы не виден.
- **Заметка = файл** `<slug>.md`. Slug из заголовка (транслит кириллицы, нижний регистр, дефисы, максимум 60 символов), коллизии разрешаются суффиксом `-2`, `-3`. **Имя файла следует за заголовком:** сменил заголовок — файл переехал. Держится это на том, что ссылки между заметками идут по id, а не по пути (§8.9), и на том же id идёт сверка индекса, поэтому переезд не считается удалением. Суффикс коллизии считается тем же именем — `plany-2.md` при заголовке «Планы» на месте и в `plany-3.md` не превращается. Заголовок, из которого слаг не выводится (эмодзи, иероглифы), имя не меняет: пустое имя хуже устаревшего. Транслит после появления файлов в vault менять нельзя — иначе одна заметка называется по-разному до и после переименования.
- Скрытые файлы и папки игнорируются, кроме `.trash`.
- Любой `.md`, положенный в vault извне, подхватывается; отсутствующий frontmatter достраивается **при первом сканировании**: `id` генерируется, `title` берётся из имени файла без расширения, `created` и `updated` — из mtime, каким он был до нашей записи. Уже проставленные значения не перезаписываются никогда, включая `id`, не похожий на ULID: неизвестно, чем он был и кто на него ссылается.

### 4.2. Frontmatter

```yaml
---
id: 01K3QF8ZN7X2WPBV4YHMC6TDAE   # ULID, неизменяемый
title: Перерасчёт значений свойств
created: 2026-08-18T13:12:03+03:00
updated: 2026-08-18T14:40:11+03:00
status: active                     # none | active | onHold | completed | dropped
tags: [работа, armz, баг]
pinned: false
origin: agent                      # user | agent
context:                           # опционально, заполняет агент
  repo: armz-frontend
  branch: feature/recalc
  commit: 3f9a1c2
---
```

Правила:

- `id` — ULID через `ulid.Make()`. Один раз, навсегда. По нему работают ссылки.
- `title` — единственный источник заголовка. H1 в теле заголовком **не считается**.
- `created`/`updated` — RFC 3339 с таймзоной. `updated` пишет приложение; при внешней правке берётся mtime.
- Отсутствие `status` эквивалентно `none`.
- **Неизвестные поля и порядок ключей сохраняются при перезаписи.** Отсюда требование к YAML-библиотеке: категорически нельзя декодировать в `map[string]any` или в типизированную структуру и кодировать обратно — это молча убивает порядок, комментарии, стиль кавычек и любые чужие поля. Работать через `CommentMap` goccy либо через его AST.
- Порядок ключей при записи новой заметки фиксированный (как выше) — ради чистых git-диффов.

### 4.3. Корзина

Удаление = перенос файла в `.trash/` + поля `trashedFrom` и `trashedAt`. Восстановление возвращает по сохранённому пути; **удалённый за это время ноутбук создаётся заново**, и заметка оказывается ровно там, где была. В корень она попадает только если `trashedFrom` ведёт туда, куда писать нельзя — в скрытый каталог или за пределы vault: так бывает у файла, поправленного руками, и терять из-за этого заметку нельзя. «Удалить навсегда» — `os.Remove` + коммит, только из корзины.

### 4.4. Вложения

- Вставка из буфера и drag&drop → `attachments/<год>/<месяц>/<8 символов base32>.<ext>`, в текст `![](attachments/2026/08/rr3k9q2x.png)`.
- **Путь всегда от корня vault**, не относительно заметки: приложение резолвит сам. Осознанный трейд-офф — markdown чуть менее переносим наружу, зато перемещение заметки не ломает картинки.
- Ограничений по типу файла нет, не только картинки. Для не-картинок вставляется обычная ссылка.
- Команда «Найти неиспользуемые вложения» показывает список; сама ничего не удаляет.

### 4.5. Git

- **История выключена по умолчанию.** Новое хранилище — просто папка с файлами, и `.git` в ней сам не заводится: заметки должны оставаться заметками, а не требовать репозитория. Включается тумблером в настройках («Папка и файлы» → «История»), и только тогда vault инициализируется как git-репозиторий.
- Решение живёт в `.tasker/git.json` внутри самого хранилища: история — свойство папки, а не человека, и читают его два процесса, приложение и `tasker-mcp`. Файла нет — умолчание выводится из наличия `.git`: папка, в которой репозиторий уже есть, историю уже ведёт, и молча перестать значит прекратить делать то, что человек видел вчера.
- **Выключение ничего не удаляет.** Репозиторий остаётся на диске со всеми коммитами, приложение просто перестаёт в него писать; включённый обратно, он продолжает ту же историю. Удалять чужую историю по щелчку тумблера нельзя ни при каких обстоятельствах.
- **Автокоммит** с окном 90 секунд, плюс принудительно при выходе и перед массовыми операциями. Окно отсчитывается **от первой накопленной правки**, а не от последней: при непрерывной работе окно «после последнего изменения» не закрывается никогда, и обещание из §10 «больше 90 секунд работы потерять физически невозможно» перестаёт выполняться.
- Сообщения: `notes: <N> изменено` либо `notes: <title>`; от агента — `agent: create "<title>"`, `agent: append "<title>"`.
- Push никуда не делается: репозиторий локальный.
- «История заметки» в UI = `git log --follow` по файлу, diff двух ревизий, «Восстановить эту версию» = запись старого содержимого поверх текущего (не reset).

## 5. Данные

### 5.1. Схема SQLite

Файл `.tasker/index.sqlite`, WAL — обязательно, потому что одновременно пишут приложение и `tasker-mcp`.

```sql
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;

CREATE TABLE notes (
  rowid       INTEGER PRIMARY KEY,
  id          TEXT NOT NULL UNIQUE,
  path        TEXT NOT NULL UNIQUE,
  notebook    TEXT NOT NULL,
  title       TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'none',
  pinned      INTEGER NOT NULL DEFAULT 0,
  created     INTEGER NOT NULL,
  updated     INTEGER NOT NULL,
  mtime       INTEGER NOT NULL,
  size        INTEGER NOT NULL,
  num_tasks   INTEGER NOT NULL DEFAULT 0,
  num_done    INTEGER NOT NULL DEFAULT 0,
  excerpt     TEXT NOT NULL DEFAULT '',
  trashed     INTEGER NOT NULL DEFAULT 0,
  origin      TEXT NOT NULL DEFAULT 'user'
);
CREATE INDEX idx_notes_notebook ON notes(notebook);
CREATE INDEX idx_notes_updated  ON notes(updated DESC);
CREATE INDEX idx_notes_status   ON notes(status);

CREATE TABLE tags (
  name  TEXT PRIMARY KEY COLLATE NOCASE,
  color TEXT NOT NULL DEFAULT 'default'
);

CREATE TABLE note_tags (
  note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  tag     TEXT NOT NULL COLLATE NOCASE,
  PRIMARY KEY (note_id, tag)
);
CREATE INDEX idx_note_tags_tag ON note_tags(tag);

CREATE TABLE links (
  src TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  dst TEXT NOT NULL,
  PRIMARY KEY (src, dst)
);
CREATE INDEX idx_links_dst ON links(dst);   -- это и есть бэклинки

CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, body,
  tokenize = 'trigram',
  content = '',
  contentless_delete = 1
);

CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

**Про токенизатор.** `trigram` — один из четырёх встроенных в FTS5, отдельного флага сборки не требует. Даёт частичное совпадение (найти «trin» внутри «string»), одинаково работает с русским и с кодом, плюс делает индексируемым `LIKE '%foo%'`. Ограничение: подстроки короче трёх символов не находятся никогда. Inkdrop перешёл на него же.

**Про `contentless_delete`.** Флаг добавлен по итогам дымового теста фазы 0 и обязателен. Без него `content=''` не позволяет удалить строку из индекса, не передав старое содержимое, — а при удалении файла его уже нет. Проверено там же: `UPSERT` на виртуальной таблице не поддерживается вовсе, поэтому обновление строки делается парой `DELETE` + `INSERT` в одной транзакции.

**Дымовой тест FTS5 пройден в фазе 0** (`oak-go/phase0/fts5`): `modernc.org/sqlite` v1.56.0 несёт SQLite 3.53.3 с `ENABLE_FTS5` без build-тега, `trigram` находит подстроки внутри слов, кириллица регистронезависима вместе с «ё». 10 000 заметок по ~2 КБ: индекс строится 2 с, файл 47 МБ.

### 5.2. Синхронизация индекса

- При старте — обход vault, сравнение `(path, mtime, size)` с таблицей: изменённые перечитать, пропавшие удалить, новые добавить.
- В рантайме — watcher.
- `meta.schema_version` не совпал с версией в коде → индекс сносится и строится заново. Всегда безопасно, правда в файлах.
- Полная переиндексация 10 000 заметок — несколько секунд. Не укладывается — профилировать, а не усложнять схему.
- Одно соединение на запись, сериализованное через одну горутину. Wails-сервисы — синглтоны, вызовы из вебвью приходят конкурентно, никто их за тебя не сериализует.

### 5.3. Watcher — читать внимательно

На macOS **fsnotify использует kqueue, а не FSEvents**. Отсюда три следствия, которые надо заложить в архитектуру, а не обнаружить потом:

1. **Рекурсивного слежения нет.** Дерево обходится самостоятельно, watch вешается на каждую папку, при создании папки — довешивается.
2. **Дескриптор тратится на каждый файл, а не на каждый watch — и с этим ничего не поделать.** Изначально здесь было написано, что наблюдение только за папками переводит расход с O(файлов) на O(папок). **Это неверно для fsnotify.** Замерено 2026-08-20 на v1.10.1: `Add` одной папки с 500 файлами добавляет 504 дескриптора, `WatchList` при этом показывает одну запись. Библиотека сама вешает kqueue на каждый файл внутри папки — иначе она не заметила бы правку содержимого, потому что vnode-событие каталога срабатывает только на добавление и удаление записей.

   Плата за это честная: **правка на месте, без временного файла, замечается** — а при наблюдении за одними лишь папками она была бы не видна. Расход: 10 000 заметок → 10 104 дескриптора. На macOS 26 это в пределах нормы (`kern.maxfilesperproc` 184320, а Go с 1.19 сам поднимает мягкий лимит до жёсткого при старте), но следить за этим надо: ошибка «too many open files» приходит через `Errors`, и по ней watcher переходит на одну лишь периодическую сверку.
3. **Нечитаемый элемент глушит весь каталог, и молча.** Замерено 2026-08-20 на fsnotify v1.10.1: если внутри наблюдаемой папки лежит файл или подпапка, которую нельзя открыть, событий по этой папке не приходит вообще — ни одного. `Add` при этом возвращает `nil`, в `Errors` тоже ничего. Обойти средствами библиотеки нечем: она пытается открыть каждый элемент сама. Отсюда прямое следствие — **периодическая сверка не «на всякий случай», а единственное, что в такой ситуации работает**, и выключать её нельзя ни при каких условиях.

4. Альтернативы отвергнуты сознательно: `fsnotify/fsevents` сам себя описывает как нестабильный и плохо поддерживаемый, с жёстким лимитом 4096 путей; `rjeczalik/notify` умеет рекурсию и FSEvents, но последний релиз в январе 2023 и до сих пор v0.

Watcher — **оптимизация задержки, а не источник правды.** Периодическая сверка по mtime раз в несколько минут ловит всё, что он проспал.

Дебаунс 200–500 мс обязателен: атомарная запись (временный файл → rename) выглядит как шторм из CREATE + RENAME + CHMOD, плюс macOS постоянно шуршит `.DS_Store`.

**Гонка редактора и watcher — самая сложная задача в проекте, и её не решает ни один фреймворк.** Решение: реестр «своих» записей (путь + ожидаемый mtime), события по ним игнорируются 2 секунды. Плюс явное правило: пока заметка открыта в редакторе и в ней есть несохранённые изменения, внешнее изменение файла **не затирает буфер**, а показывает плашку «файл изменён снаружи» с выбором.

## 6. Процессы и граница Go ↔ JS

```
┌──────────────────────────────────────────────┐
│ tasker (Wails v3)                            │
│  Go: сервисы поверх internal/*               │
│      vault · index · watcher · gitstore      │
│   ↕ сгенерированные TS-биндинги + события     │
│  WKWebView: React + CodeMirror 6             │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ tasker-mcp — отдельный бинарник, stdio          │
│  импортирует те же internal/*                │
│  работает при закрытом приложении            │
└──────────────────────────────────────────────┘
```

### Биндинги

Wails v3 статически анализирует исходники и генерирует TypeScript в `frontend/bindings/`. Экспортированные методы сервисов биндятся автоматически, регистрировать вручную не нужно. Сигнатуры типизированы, `Promise<T>` соответствует возвращаемому типу Go, doc-комментарии Go попадают в TS и видны при наведении. `wails3 dev` перегенерирует их в watch-режиме.

**`frontend/bindings/` руками не редактируется никогда.**

### События Go → JS

`app.Event.Emit("tasker:notes-changed", payload)` на стороне Go, `Events.On('tasker:notes-changed', cb)` на стороне JS. Именование: префикс `tasker:` для своих событий, `common:` / `mac:` — системные Wails.

События, которые шлёт ядро:

| Событие | Когда |
| --- | --- |
| `tasker:notes-changed` | индекс обновился (список заметок надо перечитать) |
| `tasker:note-changed` | конкретная заметка изменилась на диске |
| `tasker:index-rebuilding` / `tasker:index-ready` | полная переиндексация началась/закончилась |
| `tasker:external-edit` | открытая заметка изменена снаружи |

**Event hooks с отменой** — фича v3, которой не было в v2: перехват `common:WindowClosing`, чтобы дописать буфер и сделать финальный коммит до закрытия. Использовать обязательно.

### Что живёт на стороне JS

Только то, что физически не может жить в Go: состояние CodeMirror, режимы отображения, скролл, фокус, анимации, локальный UI-стейт компонентов. Всё остальное — вызов биндинга.

## 7. Интерфейс

Три колонки:

```
┌──────────┬────────────────┬──────────────────────────────┐
│ Сайдбар  │ Список заметок │ Редактор / превью            │
│ Все      │ [поиск]        │ Заголовок                    │
│ Активные │ ▸ Заметка 1    │ [ноутбук] [теги] [статус]    │
│ НОУТБУКИ │ ▸ Заметка 2    │ ─────────────────────────    │
│ ТЕГИ     │                │ CodeMirror                   │
│ Корзина  │                │                              │
└──────────┴────────────────┴──────────────────────────────┘
```

Ширины тянутся и запоминаются. `Cmd+/` прячет сайдбар и возвращает его; кнопка для того же стоит в полосе списка и остаётся на месте, когда сайдбара нет. Свёрнутый сайдбар фокус не принимает — `Ctrl+Shift+H/L` его пропускают.

**Масштаб текста:** `Cmd+=`, `Cmd+-`, `Cmd+0`, границы 0.8–1.6. Растёт только кегль — ширины колонок остаются, поэтому на экране столько же колонок, просто читать легче. Высота строки списка растёт вместе с текстом и считается в одном месте (App), потому что на ней стоит арифметика виртуализации. Не зум вебвью: тот увеличивает всё разом, включая ширины, и в окно попросту влезает меньше.

**Иконка** лежит готовыми размерами в `build/darwin/icon` и собирается в `icons.icns` задачей `generate:icons`. Не одной картинкой через `wails3 generate icons`: мелкие размеры нарисованы отдельно, без точечной вуали, и даунскейл 1024-й превратил бы её в кашу. Icon Composer (`appicon.icon` → `Assets.car`) не используется — иконка нарисована готовой плиткой со своим скруглением, а он накладывает поверх собственную форму.

**Меню приложения — своё, а не стандартное от Wails.** Стандартное забирает `⌘+`, `⌘-` и `⌘0` под масштаб вебвью, а ускорители меню в macOS перехватывают клавишу до вебвью: обработчик в интерфейсе не вызывается вовсе, и переназначить их через `keymap.json` невозможно. В своём меню остались только системные роли — буфер обмена, окно, справка; команды приложения живут в `keymap.json`.

Верхние **42 пикселя во всех трёх колонках** отданы под перетаскивание окна за скрытый заголовок. Перетаскивание задаётся разметкой (`--wails-draggable: drag`), а не высотой невидимого заголовка: тот вариант тянет окно на любой щелчок в полосе, без исключений. Свойство наследуется, поэтому всё, что кладут на полосу, обязано отменить его у себя.

В полосе сайдбара, на одном уровне с системным светофором, стоит **шестерёнка настроек**. В полосе списка — кнопка сворачивания сайдбара. Когда сайдбар свёрнут, полоса списка становится самой левой: она берёт на себя отступ под светофор и показывает шестерёнку у себя, иначе настройки исчезли бы вместе с сайдбаром.

**Палитра — нейтральная серая шкала, цвет только в акценте, статусах и тегах** (`theme/palette.css`, закреплена дизайн-хендоффом в `docs/design_handoff_tasker`). Дубовая палитра первой редакции отменена: приложение открыто часами, и цветной хром на такой дистанции утомляет.

- Тема выбирается атрибутом `data-theme` на `<html>`: `dark` (по умолчанию), `light`, `auto` (по системе).
- Акцент — атрибутом `data-accent`, шесть готовых: графит, сталь (по умолчанию), шалфей, лаванда, хаки, глина. Ограничение по яркости не вкусовое: в тёмной теме S 18–28% / L 58–70%, в светлой тот же оттенок при L 26–44%.
- И то и другое правится на экране настроек (`⌘,`) и лежит в `.tasker/config.json`.
- Прозрачность и размытие панелей: окно создаётся `MacBackdropTranslucent` **всегда**, а плотность решает CSS — рантаймового переключателя у Wails нет. Редактор на 30 пунктов плотнее списка. На батарее прозрачность отключается, если это включено в настройках.
- Теги: 14 оттенков по кругу с шагом 26°; насыщенность и светлота общие и живут в CSS, потому что различаются между темами.

Пользовательский `~/.tasker/styles.css` **пока не грузится** — обещание не выполнено.

### Экран настроек

Оверлей 820×600 поверх главного окна (макет T6), навигация 196 px слева.
Не второе окно: настройки применяются сразу, и двум окнам пришлось бы
синхронизировать состояние событием ради экрана, который открывают раз в месяц.

| Раздел | Что настраивается |
| --- | --- |
| Внешний вид | оформление, акцент (6 готовых плюс свой оттенок), прозрачность, размытие, экономия, порядок и видимость верхних пунктов сайдбара |
| Папка и файлы | путь к хранилищу и его смена, недавние, сводка, пересборка индекса, история и окно автокоммита |
| Редактор | образец текста, кегль, интерлиньяж, номера строк, перенос, задержка автосохранения, вим и его движения |
| Шоткаты | все команды по контекстам, перебинд нажатием, конфликты, сброс |
| Агент | что делал агент, метка в списке, путь к `tasker-mcp`, готовая команда `claude mcp add` и конфиг для Claude Code |
| О программе | версии, где что лежит |

**Vim-режим выключается двумя тумблерами** — в редакторе и отдельно движения
`j`, `k`, `h`, `l` в списке, сайдбаре и при смене колонки (§8.6). Оба включены по умолчанию и
таковыми остаются: выключатель существует не ради выбора «как настроить», а
ради человека, который вима не знает, — для него редактор в нормальном режиме
не «настроен иначе», а просто не печатает. Стрелки, `⏎` и остальные команды
работают при любом положении тумблеров.

## 8. Функциональные требования

Формат: требование — критерий приёмки.

### 8.1. Ноутбуки

- Дерево в сайдбаре, произвольная вложенность, разворачивание с запоминанием.
- Счётчик заметок. **Свёрнутый** ноутбук считает вложенные, **развёрнутый** — только свои.
- Создание, переименование (`git mv` папки), удаление (содержимое → в корзину).
- Drag&drop заметки на ноутбук перемещает файл.
- Иконка: эмодзи или встроенный SVG, хранится в `.tasker/notebooks.json`.
- Порядок ручной, по умолчанию алфавитный.
- **Критерий:** перемещение заметки сохраняет `id`, ссылки продолжают работать, картинки не ломаются.

### 8.2. Теги

- Много на заметку, поле с автокомплитом под заголовком.
- Цвет из палитры (14 значений), выбирается вручную. **Хранится в `.tasker/tags.json`, а не в `tags.color`:** индекс объявлен производным и сносится при смене схемы (§5.2), а выбранный цвет — пользовательские данные. Индекс подтягивает цвета из файла при каждой сверке, поэтому `list_tags` по-прежнему отвечает одним запросом. Тег без выбранного цвета получает постоянный оттенок, выведенный из имени: без цвета не остаётся никто.
- Клик по тегу фильтрует список, несколько тегов — по И.
- **Критерий:** переименование тега проходит по всем заметкам, переписывает frontmatter, одной операцией и одним коммитом.

### 8.3. Статусы

- `none` / `active` / `onHold` / `completed` / `dropped`, шоткаты `Cmd+Ctrl+1..5`.
- `completed` и `dropped` скрыты из списка ноутбука по умолчанию, доступны отдельными пунктами сайдбара.
- Псевдо-ноутбук «Активные» — `active` + `onHold` из всех ноутбуков по дате изменения. Главный экран рабочего дня.
- **Критерий:** смена статуса мгновенно убирает заметку из списка, если она перестала подходить под фильтр.

### 8.4. Список заметок

- Сортировки: заголовок / создано / изменено, обе стороны. Запоминается.
- Закреплённые сверху отдельной группой.
- В строке: заголовок, дата, две строки текста, теги, статус, прогресс чеклиста `3/7`.
- Мультивыбор `Cmd`+клик и `Shift`+клик.
- Массовые: в корзину, переместить, дублировать, закрепить, статус, тег.
- Клавиши: `j`/`k`, `m`, `p`, `Cmd+D`, `Cmd+Backspace`, `Enter`.
- Виртуализация: 10 000 заметок скроллятся без лагов. **Проверено 2026-08-20:** в DOM 19–20 строк вместо 10 000, первая отрисовка 19 мс. Держится на одинаковой высоте строк — превью жёстко обрезано двумя строками, мета уложена в одну, — иначе окно пришлось бы считать измерением каждой строки.

### 8.5. Поиск

Одно поле, два режима: глобальный и фильтр по текущему ноутбуку.

| Синтаксис | Значение |
| --- | --- |
| `слово` | полнотекстовый по заголовку и телу |
| `"точная фраза"` | фраза целиком |
| `book:Работа` | в ноутбуке, с вложенными |
| `tag:баг` | с тегом |
| `status:active` | со статусом |
| `title:` / `body:` | только в заголовке / только в теле |
| `is:pinned` | закреплённые |
| `is:agent` | заведённые агентом (`origin: agent`) |
| `has:task` | есть незакрытые чекбоксы |
| `-tag:черновик` | отрицание, работает и с фразами |
| пробел | И |

Парсер запроса — **в Go**, в `internal/index`, с юнит-тестами на каждую форму. Запрос только из отрицаний — понятная ошибка. Совпадения подсвечиваются в открытой заметке. **Сохранённые запросы** закрепляются в сайдбар под своим именем (в Inkdrop этого нет, а нужно).

### 8.6. Редактор

- CM6 + `@codemirror/lang-markdown` с GFM.
- Подсветка кода в fenced-блоках через `@codemirror/language-data`, ленивая загрузка.
- `@replit/codemirror-vim` **включён по умолчанию**; `:w`, `:q`, `:e` привязаны к командам приложения. Выключенный не подменяется заглушкой, а просто не добавляется расширением: остаётся обычный CodeMirror с `defaultKeymap`, без режимов и без ex-команд, и строка статуса режим не показывает.
- Мультикурсор, `Cmd+D` на выделении, move/copy line, join, sort lines.
- Find & replace в заметке, regex и регистр.
- Умное продолжение списков: маркеры, нумерация с автоинкрементом, чекбоксы; двойной Enter выходит; Tab/Shift+Tab меняют уровень.
- **Отступ блока:** `Cmd+]` и `Cmd+[` в любом режиме, плюс `Tab`/`Shift+Tab`, когда выделение задевает больше одной строки. Привязки идут выше вима — его кеймап стоит первым и `Tab` иначе забирает себе. Выделение внутри одной строки остаётся за набором: там `Tab` обязан печатать.
- Таблицы: Tab по ячейкам, Enter в последней строке добавляет новую; переформатирование по команде, не на каждый символ.
- Автокомплит: `[[` по заголовкам заметок, `:` эмодзи, ключевые слова языка в блоках кода. **Источник данных для `[[` — запрос в Go, не список в памяти JS.**
- **Плавающий тулбар над выделением:** болд, курсив, зачёркнутый, `==выделение==`, код в строке, блок кода и алерты GitHub. Появляется только при непустом выделении — над кареткой ему нечего делать, а постоянная панель в редакторе markdown лишняя: разметку здесь чаще набирают руками. Вся логика разметки — чистые функции над строкой, с таблицей тестов: сложность в границах (маркеры снаружи выделения, уже размеченный блок, пустое выделение), а не в самих обёртках. Позиционируется абсолютно внутри колонки редактора, а не fixed в окне: у колонки `backdrop-filter`, а он создаёт содержащий блок для позиционированных потомков.
- Слэш-команды, отключаемая панель форматирования.
- Тогглы: номера строк, перенос, ширина колонки.
- **Критерий:** vim не конфликтует ни с одним шоткатом; `Esc` в insert уходит в normal, а не сбрасывает поиск.

### 8.7. Markdown

GFM целиком, сноски, GitHub-alerts (`> [!NOTE]` и четыре остальных), `<sub>`/`<sup>`/`<kbd>`, `==выделение==`, HTML-комментарии как скрытый текст, атрибуты блока кода, цветовые свотчи, KaTeX, mermaid.

Эмбеды YouTube и твитов — **не делаем**.

### 8.8. Превью

- `unified` → `remark-parse` → `remark-gfm` → `remark-math` → `remark-rehype` → `rehype-katex` → JSX.
- Три режима: редактор / превью / рядом. `Cmd+E` и `Cmd+P`.
- Синхронный скролл по позиции строки исходника, не по проценту.
- Клик по чекбоксу правит исходник.
- Блоки кода подсвечиваются тем же набором `--syntax-*` переменных, что и редактор.
- Mermaid с pan/zoom.

### 8.9. Связи

- Формат `[Заголовок](tasker://note/<ULID>)`, рендерится актуальным заголовком цели.
- **Переход по ссылке:** `Cmd`+щелчок по адресу в тексте. Через `Cmd`, потому что редактор показывает исходник и обычный щелчок обязан ставить каретку; `Cmd`+щелчок в CodeMirror ставит второй курсор, и он забирается только над самой ссылкой — в остальных местах мультикурсор остаётся (§8.6). Подчёркивание не украшение: без него ссылка в исходнике неотличима от текста, и щёлкать по ней никто не догадается. Класс символов адреса совпадает с `reNoteURL` в `internal/index/record.go` — подчёркивается ровно то, что Go проиндексировал.
- Если цель не попадает в текущий отбор, отбор сбрасывается на «Все заметки»: заметка грузится по id и открылась бы всё равно, но в списке слева не подсветилась бы ничем, а операции над выделением искали бы её там, где её нет.
- `[[` — автокомплит, вставляет ссылку в этом формате.
- «Скопировать ссылку на заметку».
- Клик по битой ссылке предлагает создать заметку.
- **Бэклинки:** счётчик в метаполосе редактора раскрывается списком заголовков, каждый открывает свою заметку. Панелью под редактором это станет позже; `SELECT src FROM links WHERE dst = ?` уже отдаёт готовые записи.
- Граф связей — **не делаем**.

### 8.10. Шаблоны

- Папка `templates/`, любой `.md` в ней — шаблон.
- `Cmd+T` на пустой заметке: пикер с фильтрацией и превью, недавние сверху.
- Блок `_template` во frontmatter задаёт свойства создаваемой заметки:

```yaml
---
_template:
  title: "Баг: "
  notebook: Работа/Баги
  tags: [баг]
  status: active
---
```

- Плейсхолдеры: `{{date:2006-01-02}}` (формат времени Go, не strftime), `{{time}}`, `{{uuid}}`, `{{cursor}}`. Незнакомый плейсхолдер остаётся текстом: шаблон правит человек, и молча съедать непонятое — худший из вариантов. `{{cursor}}` считается по уже раскрытому тексту, и метка одна: кареток в редакторе тоже одна.
- Применение шаблона не затирает уже проставленные теги и статус. Статус остаётся, если он не `none`; теги дополняются, а не заменяются; заголовок берётся из шаблона только когда задан в `_template`. Тело заменяется целиком — накладывать шаблон поверх написанного бессмысленно.
- **Шаблон накладывается на уже заведённую заметку**, а не создаёт новую: иначе появился бы второй путь создания со своими правилами имени файла, id и коллизий. Отсюда и глобальное сочетание — жмут его из открытой заметки.
- Файлы шаблонов лежат в хранилище обычными заметками и попадают в индекс наравне с остальными: файлы — источник правды, и прятать часть из них значит заводить второе правило о том, что считается заметкой.

### 8.11. Клавиатура

- **Палитра команд** `Cmd+K`: fuzzy по командам, ноутбукам, тегам и заголовкам. Префиксы `>` команды, `#` теги, `@` ноутбуки, без префикса — заметки. Фильтрация — запросом в Go.
- Кеймап в `~/.tasker/keymap.json`, именованные контексты: `global`, `sidebar`, `note-list`, `editor`. Контекст `modal` не заведён: у модалок свои обработчики, спорить за клавишу там не с чем.
- **Индикатор фокуса колонки существует только при включённых движениях вима.** Он отвечает на вопрос «где я» после переключения вслепую, а вслепую переключают ровно `⌃⇧H` и `⌃⇧L`; сняли движения — сняли и переключение, и полоса пропадает целиком, а не гаснет в точки. Фокус при этом всё равно переезжает — `⏎` в текст, `esc` обратно, щелчок по колонке, — но там он переезжает на глазах.
- **Смена колонок — вимовская навигация целиком**, поэтому дублёра на стрелках у неё нет, в отличие от движений внутри колонки (`j`/`k` в списке, `h`/`l` в дереве), где дублёр обязателен: отказ от вима не должен отнимать навигацию по содержимому. На обе половины правила есть тесты.
- Сам индикатор — блочная ASCII-рампа в полосе перетаскивания, на одной линии с системными кнопками окна (спека ставит её по верхней кромке; сдвинуто по решению владельца — на кромке она читалась как оторванная). Высота линии задаётся одним числом `--ramp-top`: светофор рисует macOS, из CSS его не измерить, а у titlebar в режиме hiddenInset кнопки сидят заметно ниже верха. Там, где полоса отдана светофору, рампа начинается за ним — иначе центрирование по ширине колонки завело бы её прямо под кружки. Спецификация в остальном — по спецификации `docs/design_handoff_tasker/FOCUS-STRIP.md`: длина зависит от колонки (11 / 17 / 23 символа), неактивные показывают точки, неактивное окно гасит все три. Высоты у содержимого не отнимает. **Отступление от спеки:** заливка анимирована от концов к центру, 180 мс — спека просит обходиться без анимации, решение принято владельцем. Маска обязана быть с `-webkit-` префиксами и на блочном боксе: вебвью здесь Safari, а на строчном элементе маска молча не применяется.
- **Фокус ходит по трём колонкам:** `Ctrl+Shift+L` правее, `Ctrl+Shift+H` левее, по кругу. **Инвариант: у каждого вимовского движения внутри колонки в умолчаниях есть невимовый дублёр**, и это проверяется тестом; у смены колонок дублёра нет намеренно — см. выше. Из текста тоже — сочетание перехватывается в фазе погружения, иначе выйти из редактора клавиатурой было бы нельзя. С шифтом, потому что голые `Ctrl+H` и `Ctrl+L` в CodeMirror заняты (backspace и «выделить строку») и при наборе нужны тексту; `Ctrl+Shift+*` не занимает ни вим, ни редактор, поэтому работает и в режиме вставки, без предварительного `Esc`.
- Правило перехвата общее, а не список: одинокий `Ctrl` с клавишей — территория текста и в режимах набора не отбирается; всё с `Shift` или `Cmd` перехватывается всегда.
- **Фокусная колонка помечается цветом выбранного, а не полосой на стыке:** выделение горит акцентом там, где сейчас работают, и гаснет до серого в остальных колонках — как в Finder. У редактора отдельной пометки нет, там виден курсор.
- Сайдбар управляется с клавиатуры: `j`/`k` по строкам, `Enter` открыть, `h`/`l` свернуть и развернуть ветку.
- `Cmd+,` открывает настройки — как во всех приложениях macOS.
- **Сочетания не зависят от раскладки:** нажатие приводится к латинице по физической позиции клавиши, той же таблицей, что и вим. Иначе при ЙЦУКЕН не работает ни одно буквенное сочетание.
- Multi-stroke биндинги (`space e`, `g g`) — **не сделано**.
- Глобальный системный хоткей: показать окно и быстрая заметка — **не сделано**.
- **Поиск по настройкам** в колонке разделов: находит по подписи и по словам, которых в подписи нет («тёмная» ведёт в «Оформление»). Подменяет список разделов, а не соседствует с ним, и подписывает раздел у каждой находки — настройку надо уметь найти второй раз уже руками. Список для поиска живёт отдельным файлом, потому что разметка — это JSX и вытаскивать подписи из неё в рантайме нечем; цена — второй список, и на неё есть тест: каждый раздел обязан быть в поиске представлен.
- Экран всех шоткатов — раздел «Шоткаты» в настройках: команды по контекстам, перебинд нажатием, занятое сочетание назначить не даёт, однобуквенная привязка в контексте редактора предупреждает про вим. Поиска по списку нет: команд полтора десятка.
- История просмотра: `Cmd+[` / `Cmd+]`, кнопки мыши 3/4, свайп тачпадом.

### 8.12. Окна

Несколько окон приложения, заметка в отдельном окне, быстрая заметка по глобальному хоткею, полноэкранный режим, размер шрифта, запоминание геометрии.

Всё это — прямая причина выбора Wails v3: в v2 мультиоконности нет.

### 8.13. Картинки

**Сделано:** вставка из буфера и drag&drop кладут файл по §4.4 и вставляют разметку на место каретки; картинка показывается в редакторе **под** строкой, в которой упомянута, а не вместо разметки — это редактор исходника, и прятать то, что человек правит, нельзя. Высота ограничена: снимок экрана в полный рост выталкивает текст из окна.

Файлы хранилища отдаются вебвью раздатчиком по префиксу `/vault/`, а не data-URI: картинка на несколько мегабайт, вшитая в документ, перерисовывается вместе с ним на каждое нажатие. Префикс отдельный, потому что фронтенд и хранилище живут в одном адресном пространстве и заметка с именем `index.html` иначе подменила бы приложение. Путь приходит из markdown, то есть из файла, который правят чем угодно, и проверяется тем же правилом, что и всё в vault: не наружу и не в скрытые каталоги.

**Ещё не сделано:** ресайз через alt-текст (`![width:200px]`, `![w:320 h:240]`), тулбар размера Auto / 30% / 50% / 100%, полноэкранный просмотрщик, копирование и сохранение.

## 9. Что явно не входит в объём

- Любая синхронизация, аккаунты, шифрование, шаринг в веб.
- Мобильное приложение.
- Система плагинов, публичный API.
- AI внутри приложения: автокомплит, ассистент, хранение ключей.
- Импорт из Evernote / Apple Notes / Bear / Notion / Kindle.
- Браузерный клиппер, локальный HTTP-сервер, Alfred/Raycast.
- Граф связей, эмбеды.
- Экспорт в PDF/HTML (печать из превью закрывает вопрос).
- Windows и Linux сборки.

## 10. Риски

| Риск | Насколько серьёзно | Снятие |
| --- | --- | --- |
| **Wails v3 в бете** | Средне | Беты выходят каждые 1–3 дня, API десктопа объявлен стабильным и используется в проде. Пинить точную версию в `go.mod`, читать changelog на каждом апгрейде, ожидать регрессий в кодогенерации биндингов. Запасной вариант — v2.15.0, но тогда без мультиоконности. |
| **WKWebView вместо Chromium** | **Высоко для этого проекта** | Разрабатываешь в Chrome, а работать будет в движке Safari, версия которого прибита к версии macOS. CodeMirror 6 целиком живёт в `contenteditable` и composition events — ровно там, где WebKit и Blink расходятся. Проверять **в первую неделю**: русская раскладка, мёртвые клавиши, автозамена кавычек, системная проверка орфографии, поведение при выделении мышью. Отладка — через Web Inspector Safari, не Chrome DevTools. |
| Гонка редактора и watcher | Высоко | См. §5.3. Это придётся решать самому, фреймворк не поможет. |
| FTS5 в modernc не заведётся | Низко | Дымовой тест в фазе 1. Если вдруг — переход на `github.com/ncruces/go-sqlite3` (тоже без cgo, SQLite через wasm). |
| Потеря заметок | Низко | Файлы пишутся атомарно и сами по себе — это и есть хранилище. С включённой историей сверху ложится git с автокоммитом, и тогда больше 90 секунд работы потерять физически невозможно; с выключенной теряется история, но не заметки. Никогда не вызывать `git reset --hard`, `git clean`, force-push. |
| Два тулчейна | Средне | Когда ломается `wails3 dev`, отлаживаешь Task, Vite и Go одновременно. Taskfile в v3 хотя бы читаемый, в отличие от магии v2. |
| Подпись и нотаризация | Средне | `wails3 task darwin:sign:notarize` есть, автообновления нет. **Собрать подписанный и нотаризованный `.dmg` и запустить его на втором маке — в первую неделю, а не на шестой месяц.** Классический способ угробить проект — обнаружить проблему с подписью после полугода фич. |
