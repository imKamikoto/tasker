# Tasker для агента

Справочник по тому, что в проекте есть и как оно устроено. Читать перед тем,
как что-то менять; `CLAUDE.md` рядом говорит **как** работать, этот файл —
**с чем**.

Порядок чтения для первого раза: `CLAUDE.md` → этот файл → раздел `docs/SPEC.md`
по своей задаче. `docs/DESKTOP.md` — если не работал с десктопом раньше.

---

## 1. Что это

Локальный markdown-редактор заметок-как-задач под macOS. Три особенности, ради
которых он существует (SPEC §1):

1. Редактор, в котором приятно печатать: CodeMirror 6 с вимом.
2. Заметка = задача: статус, закрепление, теги.
3. **Агент — полноправный клиент** через MCP, а не «AI-фича внутри».

Стек: Go 1.25+ · Wails v3.0.0-beta.9 · modernc.org/sqlite · React 19 + CM6.

Готовы фазы 0–4 из `docs/ROADMAP.md`. Приложение работает: список, редактор с
вимом, поиск, статусы, корзина, теги, массовые операции. Не сделаны фазы 5–8:
превью markdown, палитра команд, ссылки между заметками, картинки, шаблоны.

## 2. Три бинарника

| Что | Зачем | Нужен ли Wails |
| --- | --- | --- |
| `cmd/tasker` | приложение с окном | да, cgo обязателен |
| `cmd/tasker-mcp` | MCP-сервер для Claude Code | нет, статический бинарник |
| `cmd/tasker-scan` | отладочный CLI поверх ядра | нет |

действительно в Go. В день, когда он перестанет собираться без фронтенда,
граница поехала.

## 3. Слои

```
cmd/tasker ──┐                    cmd/tasker-mcp ──┐
             ▼                                     ▼
      internal/app  (Wails: сервисы, события)      │
             │        ← только здесь Wails         │
             ▼                                     ▼
                    internal/notes
        операции уровня заметки: файл + индекс + коммит вместе
                          │
        ┌─────────────────┼──────────────────┐
        ▼                 ▼                  ▼

   файлы, .md       SQLite, FTS5        история
                          ▲
                   internal/watcher

```

**`internal/notes` — главный слой.** «Создать заметку» это файл, строка индекса
и коммит **вместе**, и та же связка нужна и приложению, и MCP. В `internal/app`
её положить нельзя: там Wails, а MCP обязан оставаться бинарником без него.

Ни один пакет ниже `internal/app` не импортирует Wails. Это проверяемо: они
собираются и тестируются обычным `go test`.

## 4. Инварианты

Нарушать нельзя. Полный список в `CLAUDE.md`, здесь то, что чаще всего задевают.

**Файлы — источник правды, индекс производный.** Индекс сносится и строится
заново без потери данных. Отсюда следствие, о которое уже спотыкались: всё,
что пользователь выбрал руками, в индексе жить не может. Цвета тегов поэтому
лежат в `.tasker/tags.json`, а не в колонке `tags.color`.

**Запись `.md` только атомарная**: временный файл рядом → `fsync` → `rename` →
`fsync` каталога. `vault.WriteFileAtomic` — единственный способ.

**Неизвестные поля frontmatter сохраняются.** `internal/vault/frontmatter.go`
работает поверх AST goccy, а не структур: декодирование в структуру и обратно
молча убивает чужие поля, порядок ключей и комментарии. Неизменённый заголовок
отдаётся байт в байт.

**Никогда не звать** `git reset --hard`, `git clean`, `git checkout -- .`,
force-push. На это есть тест, который сканирует исходники `internal/gitstore`.

**Вся логика в Go.** Фронтенд не парсит frontmatter, не строит запросы, не
ходит в файловую систему. Понадобилось «по-быстрому распарсить в JS» — это
ошибка проектирования, метод добавляется в Go.

## 5. Справочник

### internal/vault — файлы

Работает с одной заметкой. Ничего не знает про индекс и git.

```go
Open(root string) (*Vault, error)          // EvalSymlinks сразу: пути сравниваются реальные

(*Vault) Load(path string) (*Note, error)
(*Vault) Create(n NewNote) (*Note, error)
(*Vault) Save(n *Note) error               // не пишет, если ничего не менялось
(*Vault) Move(n *Note, notebook string) error
(*Vault) Trash(n *Note) error              // + trashedFrom, trashedAt
(*Vault) Restore(n *Note) error
(*Vault) Delete(n *Note) error             // только из корзины
(*Vault) Backfill(n *Note) (bool, error)   // дописать id/title/даты файлу извне
(*Vault) EnsureNotebook(notebook string) (string, error)
(*Vault) RemoveEmptyNotebook(notebook string) error
(*Vault) OnWrite(fn func(path string, modTime time.Time))  // для watcher

NewID() string          // ULID
ValidID(s string) bool
Slug(title string) string
WriteFileAtomic(path string, data []byte, perm os.FileMode) error
```

`Note` = `Doc *Document` + `Path` + `Notebook` + `ModTime` + `Size`.
`Document` = `Meta *Frontmatter` + `Body string`.

Ошибки: `ErrNoteNotFound`, `ErrOutsideVault`, `ErrHiddenPath`, `ErrEmptyTitle`,
`ErrAlreadyTrashed`, `ErrNotTrashed`, `ErrInvalidStatus`, `ErrInvalidOrigin`,
`ErrInvalidFrontmatter`, `ErrNameCollision`.

### internal/index — SQLite и поиск

```go
Open(ctx, path string) (*Index, error)
(*Index) Put(ctx, r Record) error          // вставка или обновление по id
(*Index) Get(ctx, id string) (Record, error)
(*Index) GetByPath(ctx, path string) (Record, error)
(*Index) Delete(ctx, path string) error
(*Index) Search(ctx, q Query, opts SearchOptions) ([]Record, error)
(*Index) Scan(ctx, v *vault.Vault) (ScanResult, error)   // полный и инкрементальный
(*Index) States(ctx) (map[string]FileState, error)
(*Index) Notebooks(ctx) ([]Notebook, error)              // только с заметками
(*Index) Tags(ctx) ([]Tag, error)
(*Index) Counts(ctx) (Counts, error)                     // счётчики верхних пунктов сайдбара
(*Index) LastAgentWrite(ctx) (time.Time, error)
(*Index) Reset(ctx) error                                // снести и создать схему заново
(*Index) Size() int64                                    // размер файла индекса
(*Index) Backlinks(ctx, id string) ([]Record, error)
(*Index) ApplyTagColors(ctx, colors map[string]int) error

ParseQuery(input string) (Query, error)    // язык из SPEC §8.5
Excerpt(body string) string
CountTasks(body string) (total, done int)
ExtractLinks(body string) []string
```

`SearchOptions`: `Limit`, `Trash` (`TrashHidden` / `TrashIncluded` / `TrashOnly`),
`HideCompleted`, `Sort` (`SortUpdated` / `SortCreated` / `SortTitle` + `Reversed`).

Язык запросов: `слово`, `"фраза"`, `book:`, `tag:`, `status:`, `title:`, `body:`,
`is:pinned`, `is:agent`, `has:task`, отрицание минусом, пробел = И. **ИЛИ в языке нет** —
поэтому «Активные» (active ИЛИ onHold) сделаны отдельным методом, а скрытие
завершённых — флагом `HideCompleted`, а не запросом.

### internal/notes — операции уровня заметки

Всё под межпроцессной блокировкой `flock` на `.tasker/vault.lock`.

```go
Open(ctx, root string, opts Options) (*Service, error)   // Options.Origin: user | agent

// одна заметка
Create · Get · Update · SetStatus · SetPinned · SetTags · Duplicate
Trash · Restore · Delete

// пачка: одна блокировка, один коммит
TrashMany · MoveMany · SetStatusMany · SetPinnedMany

// чтение
Search · Tasks · Notebooks · Tags · TagColors · Sync

// ноутбуки и теги
CreateNotebook · RenameNotebook · DeleteNotebook · RenameTag · SetTagColor
```

`UpdateParams` — **указатели**: `*string`, `*bool`. Иначе не отличить «не
передано» от «передан ноль», и любое обновление сбрасывало бы всё, о чём не
упомянули. `Body` взаимоисключающ с `Append`/`Prepend`.

### internal/app — Wails (сервисы)

| Сервис | Что даёт |
| --- | --- |
| `Notes` | операции над заметками, поверх `internal/notes` |
| `Settings` | чтение и запись `config.json`, содержимое непрозрачно |
| `Keymap` | `Load` (слияние с умолчаниями), `Save`, `Reset`, `Path` |
| `Vaults` | `Current`, `Recent`, `Choose`, `Switch`, `Forget`, `Reveal`, `Restart` |
| `Info` | `Stats`, `Rebuild`, `Paths`, `Build`, `OnBattery`, `Reveal` |
| `Git` | `Settings`, `Configure` (окно автокоммита), `CommitNow` |
| `Closing` | ответ вебвью «буфер записан, можно закрывать» |

### internal/app — Wails

Единственное место, знающее про Wails. Сервисы тонкие: разобрать аргументы и
позвать слой ниже.

- `Notes` — 25 методов, биндятся в TypeScript (см. полный список ниже).
- `Watch` — цикл watcher → сверка индекса → события в окно.
- `Closing` — перехват закрытия окна: попросить интерфейс дописать буфер.
- `Settings` — `.tasker/config.json`, непрозрачный для Go blob.
- `Keymap` — `~/.tasker/keymap.json`.

События (SPEC §6):

| Событие | Когда |
| --- | --- |
| `tasker:notes-changed` | список надо перечитать, без нагрузки |
| `tasker:note-changed` | `{id, path}` конкретной заметки |
| `tasker:before-close` | окно закрывается, дописать буфер и ответить `Closing.Ready()` |

### internal/watcher и internal/gitstore

`watcher.Start(ctx, root, Options) (*Watcher, error)` → канал `Batch{Paths, Full}`.
`Ignore(path, modTime)` гасит собственные записи.

`gitstore.Open(root)` → `Commit`, `History` (через системный git, `--follow`),
`Diff`, `Show`. `Autocommit` с окном 90 секунд существует, но приложение пока
коммитит на каждое сохранение и его не использует.

## 6. Границы

### Wails-биндинги

Генерируются из Go: `wails3 generate bindings -ts -i -clean=true -d frontend/bindings ./cmd/tasker`.
**Явный `./cmd/tasker` обязателен** — без него генератор смотрит в корень и
бодро сообщает «0 Services», не падая.

`frontend/bindings/` руками не редактируется никогда. Doc-комментарии Go
доезжают в TypeScript, `context.Context` из сигнатуры убирается.

Фронтенд зовёт биндинги только через `frontend/src/api.ts` — одно место, где
видна вся граница.

### MCP

`cmd/tasker-mcp`, девять инструментов: `search_notes`, `get_note`, `create_note`,
`update_note`, `set_status`, `list_tasks`, `list_notebooks`, `list_tags`,
`trash_note`. Схемы выводит SDK из структур — руками не писать (MCP.md §3).

Индекс сверяется **перед каждым вызовом**: приложение может быть закрыто, а
заметки правиться руками. Скан инкрементальный, ~30 мс на 10 000 заметок.

Агенту **не дано**: удалять насовсем, массово переименовывать, писать в
`config.json`, трогать git напрямую, читать вне vault.

## 8. Настройки

Четыре файла, у каждого своя причина лежать именно там.

| Файл | Что | Почему здесь |
| --- | --- | --- |
| `<vault>/.tasker/config.json` | всё состояние интерфейса | привязано к конкретному хранилищу |
| `<vault>/.tasker/tags.json` | цвета тегов | пользовательские данные, индекс их не переживёт |
| `~/.tasker/keymap.json` | раскладка клавиш | принадлежит человеку, а не набору заметок |
| `~/.tasker/vaults.json` | текущая и недавние папки | путь к хранилищу внутри хранилища не прочитать |

Правит их **экран настроек** (`⌘,`, `frontend/src/components/Settings.tsx`) —
оверлей поверх главного окна, шесть разделов. Не второе окно: настройки
применяются сразу, и двум окнам пришлось бы синхронизировать состояние
событием ради экрана, который открывают раз в месяц.

### config.json

Для Go **непрозрачен**: он читает и пишет его строкой, не разбирая. Это не
отступление от «вся логика в Go» — ширины колонок и развёрнутые ветки дерева
это состояние интерфейса, которого в Go нет и быть не должно. Разбор и границы
значений лежат в `frontend/src/settings.ts`, каждое поле проверяется отдельно:
одна испорченная настройка не утаскивает остальные.

Читается **один раз при запуске**: правка файла на лету не подхватывается.

Что в нём: ширины, сортировка, свёрнутые ветки, тема, акцент и его оттенок,
прозрачность, размытие, экономия на батарее, дизер, кегль, интерлиньяж, номера
строк, перенос, задержка автосохранения, окно автокоммита, метка агента.

Две настройки исполняет Go, и они приезжают туда **вызовом**, а не чтением
файла: окно автокоммита (`Git.Configure`) и — косвенно — прозрачность, которую
Go включает на уровне окна раз и навсегда.

### vaults.json

```json
{ "current": "/Users/me/Notes", "recent": ["/Users/me/Work/Notes"] }
```

Порядок разрешения пути при запуске: флаг `-vault` → `current` → `~/Notes`.
Флаг сильнее всего — им запускают на чужой папке, не трогая выбранную.
Записанная папка могла исчезнуть вместе с внешним диском: тогда молча уходим
к умолчанию, потому что приложение, которое не открывается, хуже приложения,
открывшего не ту папку.

**Смена требует перезапуска.** Переоткрыть хранилище на лету значит погасить и
поднять заново индекс, watcher, git и открытый буфер редактора — четыре
подсистемы, каждая со своим временем жизни, ради действия раз в полгода.
Настройки предлагают перезапуск кнопкой: `Vaults.Restart` поднимает новый
экземпляр и только потом гасит текущий.

### keymap.json

Контексты решают спор за клавишу: `j` в списке двигает выделение, в сайдбаре
ходит по дереву, а в тексте принадлежит виму. Какой контекст активен, решает
**фокус колонки** (`frontend/src/focus.ts`), а не то, стоит ли каретка в тексте.
Поиск идёт от частного к общему — контекст колонки, затем `global`. Контекст
`editor` пуст намеренно.

Исключение: если каретка в поле ввода (поиск, теги, имя ноутбука), клавиши
принадлежат ему независимо от фокуса колонки — иначе `j` в поиске двигало бы
список вместо набора.

```json
{
  "global":    { "cmd+n": "note.create", "ctrl+j": "focus.next", "ctrl+k": "focus.prev" },
  "sidebar":   { "j": "sidebar.down", "enter": "sidebar.open", "l": "sidebar.expand" },
  "note-list": { "j": "list.down", "m": "note.move", "cmd+backspace": "note.trash" },
  "editor":    {}
}
```

Формат сочетания: модификаторы в порядке `cmd+ctrl+alt+shift`, затем клавиша в
нижнем регистре. Именованные: `enter`, `escape`, `backspace`, `delete`, `tab`,
`space`, `up`, `down`, `left`, `right`.

`shift` пишется у букв и именованных клавиш, но **не** у остальных символов:
там он уже поменял сам символ, и `cmd+shift+/` с `cmd+?` были бы двумя записями
для одного нажатия. Проверяется переведённый символ, а не исходный: русская «Б»
— буква, но стоит на физической запятой и переводится в `<`, где shift учтён.

**Раскладка приводится к латинской по физической позиции клавиши**
(`frontend/src/langmap.ts`, та же таблица, что у вима). Без этого при ЙЦУКЕН не
работает ни одно буквенное сочетание: `Cmd+,` приходит как `Cmd+б`, `Cmd+N` —
как `Cmd+т`, `j` и `k` в списке — как `о` и `л`. Переводится **только
кириллица**: в русском ряду физическая `/` даёт `.`, а с шифтом `,` — те же
символы, что и в латинском, но на другой позиции, и перевод сломал бы обычную
запятую. Цена — привязка на физической `/` при ЙЦУКЕН не сработает; таких нет.

Команды: `note.create`, `note.trash`, `note.duplicate`, `note.move`, `note.pin`,
`note.settings`, `note.status.{none,active,onhold,completed,dropped}`,
`focus.next`, `focus.prev`, `list.up`, `list.down`, `list.open`,
`sidebar.{up,down,open,expand,collapse}`.

**Смена фокуса ловится в фазе погружения**, а не как остальные команды: иначе
сочетание сначала достанется CodeMirror и выйти из текста клавиатурой будет
нельзя. По умолчанию это `Ctrl+Shift+H` и `Ctrl+Shift+L` — их не занимает ни
вим, ни редактор, поэтому они работают и при наборе.

Что можно отобрать у редактора, решает `stealsFromEditor` правилом, а не
списком: одинокий `Ctrl` с клавишей — территория текста (`Ctrl+H` backspace,
`Ctrl+K` до конца строки, `Ctrl+W` слово назад, `Ctrl+Alt+H` удалить группу) и
в режимах набора не отбирается. Списком его пришлось бы сверять с двумя чужими
раскладками на каждом обновлении.

Файл **сливается** с умолчаниями, а не заменяет их: правка одного сочетания не
отменяет остальные, а новые команды появляются у всех. Пустая строка вместо
команды снимает привязку. Испорченный файл не оставляет приложение без клавиш.

Умолчания живут в `internal/app/keymap.go` — единственный источник правды.
Добавляя команду, добавь её в три места: туда, в обработчик
`frontend/src/App.tsx` и в каталог `frontend/src/commands.ts`, откуда её берёт
экран шоткатов. Каталог отдельный потому, что снятая привязка стёрла бы команду
из настроек вместе с возможностью назначить её заново. Цена — два списка,
которые обязаны совпадать; их сверяет `TestEveryDefaultCommandIsInTheCatalogue`.

Перебинд мышью: раздел «Шоткаты» записывает нажатие, занятое сочетание
назначить не даёт, а однобуквенную привязку в контексте редактора разрешает с
предупреждением — она отнимет клавишу у вима.

Multi-stroke (`g g`, `space e`) из SPEC §8.11 **ещё не сделан**.

## 9. Как проверять работу

**Тесты обязательны для `internal/*`** и пишутся до реализации там, где
поведение описывается таблицей. Сейчас 498 тестов на Go и 58 на JS.

```sh
go test ./... -count=1 -race
cd frontend && npm test        # node --experimental-strip-types, без зависимостей
```

**Мутационная проверка окупается.** Сломай реализацию в одном месте и посмотри,
поймают ли тесты. За проект так нашлось около десятка настоящих дефектов, в том
числе: инкрементальный скан не замечал правку той же длины; массовая операция
обрывалась на первой ошибке; переименование тега задваивало его в файле.

Три ловушки самой проверки, на которые я уже наступал:

- мутация **не собралась** — это не «поймана», это ничего не значит;
- мутация **эквивалентна** — поведение то же, тест ни при чём (так выяснилось,
  что явный `LOCK_UN` перед `Close` не нужен);
- скрипт мутаций может **оставить дерево изменённым**, если его убить.

**Проверять надо источник правды, а не производное.** Тест на переименование
тега читал теги из индекса, где `INSERT OR IGNORE` схлопывает дубли, — и не
видел, что во frontmatter тег задвоился.

**Снимки экрана ловят то, чего не ловят тесты.** Дважды за проект: вся проза в
редакторе была зелёной (`tags.content` покрывает весь текст), и мета-строка
списка исчезала при высоте строки 76 px. Способ: собрать временную страницу с
компонентом, поднять `vite`, снять headless-браузером, страницу удалить.

## 10. Решения, записанные по ходу

Места, где реальность разошлась со спекой. Все правки внесены в SPEC, здесь
короткий список — чтобы не открывать заново.

| Что | Как оказалось |
| --- | --- |
| FTS5 `content=''` | нужен `contentless_delete=1`, иначе строку не удалить |
| «следим только за папками» | fsnotify держит дескриптор на **каждый файл**: 10 104 на 10 000 заметок |
| нечитаемый элемент в папке | молча глушит события всей папки, `Add` возвращает `nil` |
| `modernc` = сборка без cgo | для приложения неверно: Wails без cgo не собирается вовсе |
| `--follow` в go-git | не реализован; история читается системным git |
| автокоммит «после последнего изменения» | окно от **первой** правки, иначе не закрывается никогда |
| «папки нет — в корень» при восстановлении | папка пересоздаётся; в корень только при негодном `trashedFrom` |
| цвет тега в `tags.color` | вынесен в `tags.json`: индекс производный |
| `origin` только во frontmatter | не хватило: список должен отличать заметку агента, поэтому колонка в индексе и терм `is:agent` |
| подсветка `- [x]` тегами lezer | невозможна: он видит обычный пункт списка. Свой плагин декораций, цвет инлайном — иначе спор двух классов решает порядок в сгенерированной таблице стилей |
| подсветка синтаксиса запроса в `input` | `input` не красит свои куски: под ним лежит зеркало с теми же метриками, текст самого поля прозрачный |
| прозрачность окна переключаемая на лету | у Wails только опция создания. Окно всегда `MacBackdropTranslucent`, плотность решает CSS — иначе смена настройки требовала бы перезапуска |
| состояние батареи из Go | чистого способа без cgo нет; читается `pmset -g batt`, ошибка означает «не от батареи» |
| `direction: rtl` для обрезки пути с начала | переносит ведущий слэш в хвост: `/Users/me/Notes` показывается как `Users/me/Notes/` |
| карточки настроек в колоночном флексе | сжимаются по умолчанию, и длинная подпись уезжает под нижнюю границу — нужен явный `flex: none` |
| langmap только для вима | раскладка приложения тоже её требует, иначе при ЙЦУКЕН не работает ни один буквенный шоткат. Но переводить в ней можно только кириллицу: `.` и `,` есть в обеих раскладках на разных позициях |
| CodeMirror забирает каретку при монтировании | щелчок по заметке выбрасывал из списка в текст, и `j`/`k` переставали работать сразу после выбора. Фокусом владеет App, редактор сам его не берёт |
| «фокус — это событие через растущее число» | у пересоздаваемого компонента эффект срабатывает сразу с текущим значением, то есть монтирование само выглядит как событие. Редактор пересоздаётся на каждой заметке, и после первого же `Enter` каждое `j` в списке утаскивало каретку в текст. Значение при монтировании надо запоминать и пропускать |
| прозрачный `body` под прозрачность окна | всё, что лежит между колонками, потеряло основание. Разделители в ячейках сетки красились полупрозрачным поверх подложки окна и давали сплошную белую полосу вместо тонкого стыка (`255,255,255` вместо `37,37,37`). Основание надо задавать на `.layout` |
| `InvisibleTitleBarHeight` | тянет окно на **любой** щелчок в верхней полосе: нативный обработчик, без исключений и без опоры на разметку. Кнопку туда не поставить. Правильный механизм — `--wails-draggable: drag` на самой полосе; он наследуется, и всё, что на ней лежит, отменяет его у себя |
| `⚙` без варианта отображения | macOS рисует его цветной эмодзи. Нужен `\uFE0E` (VS15), иначе шестерёнка выпадает из монохромного интерфейса |
| `text-overflow: ellipsis` на флекс-контейнере | молча не работает: получается жёсткий обрез посреди буквы. Обрезаемая часть должна быть обычным блоком |
| статус словом в строке списка | `▶ active` занимало сорок пикселей из трёхсот двадцати, и тегам не оставалось места. Глиф с цветом различает все пять статусов сам; слово осталось в подсказке и в плашке редактора |
| стандартное меню Wails | молча забирает `⌘+`, `⌘-`, `⌘0` (масштаб вебвью) и `⌘R` (перезагрузка). Ускорители меню в macOS перехватывают клавишу **до** вебвью — `preventDefault` в JS бессилен, обработчик не вызывается. Любое сочетание, которое хочет `keymap.json`, обязано быть свободно от меню |
| «масштаб» как зум вебвью | увеличивает всё разом, включая ширины колонок: соотношения те же, на экране меньше. Нужен масштаб текста — один множитель на все кегли, ширины на месте, высота строки списка считается из него же |
| замена `icons.icns` меняет иконку | не меняет: `CFBundleIconName` + `Assets.car` (Icon Composer) перебивают `.icns` на новых macOS. Иконка нарисована готовой плиткой, поэтому Icon Composer убран целиком — вместе с ключом в `Info.plist` |
| `iconutil -c icns` на любой папке | требует имя, оканчивающееся на `.iconset`, иначе отвечает «Invalid Iconset» и не объясняет, чем недоволен |
| резиновая прокрутка документа | WebKit оттягивает документ за край, даже когда прокручивать нечего, и показывает `underPageBackgroundColor` вебвью — белую, Wails её не задаёт. С прозрачным `body` это выглядит как «пролистал за пределы экрана». Документу прокрутка не нужна вовсе: `overflow: hidden` и `overscroll-behavior: none` на `html, body, #root`, а внутренним скроллерам `contain`, чтобы их пружина не дотягивалась до документа |

## 11. Чего ещё нет

Из фаз 5–8: превью markdown, палитра команд `Cmd+K`, ссылки `tasker://` с
автокомплитом по `[[`, бэклинки панелью, картинки, шаблоны, история версий в
интерфейсе, несколько окон, автообновление.

Помельче, из уже начатого: multi-stroke в кеймапе, иконки и ручной порядок
ноутбуков, перетаскивание ноутбука в ноутбук, `Autocommit` не подключён
к приложению.

Из дизайн-хендоффа (`docs/design_handoff_tasker`) **не сделано намеренно**:
палитра команд `⌘K` (фаза 6), тосты, пометка «не прочитано» у заметок агента.
Модалка конфликта сделана без мини-diff и без обещания сохранить
`<имя>.conflict.md`: ни того, ни другого приложение не умеет, а рисовать в
интерфейсе то, чего нет, нельзя. Строки в мультивыборе остались 104 px вместо
64 из макета — на этой высоте стоит виртуализация.

Не проверено на живом окне: **просвечивает ли прозрачность панелей до обоев**.
CSS и опция окна на месте, но композитинг WKWebView поверх `NSVisualEffectView`
из headless-браузера не воспроизводится. По умолчанию прозрачность нулевая, и
при ней всё красится непрозрачно, как раньше.

Известные ограничения, не баги: теги регистронезависимы только для латиницы
(`COLLATE NOCASE` в SQLite), подстроки короче трёх символов не находятся
(токенизатор trigram).
