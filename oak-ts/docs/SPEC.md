# Oak — техническая спецификация (вариант А: всё на TypeScript)

> Локальный markdown-редактор заметок и задач для macOS. Одиночный пользователь, без облака, без аккаунтов.
> Рабочее название **Oak** — переименуй, если не нравится: оно встречается только в `package.json`, в URI-схеме `oak://` и в имени папки хранилища.

Версия документа: 1.0 · Целевая платформа: macOS 13+ (Apple Silicon)

---

## 1. Зачем это существует

Три вещи, которых нет ни в одном бесплатном аналоге одновременно:

1. **Редактор, в котором приятно печатать.** CodeMirror 6 с подсветкой markdown прямо в тексте и настоящим vim-режимом.
2. **Заметка = задача.** Статус (`active` / `onHold` / `completed` / `dropped`), закрепление, теги. Завершённые уходят из списка сами.
3. **Агент — полноправный клиент.** Claude Code во время работы над кодом может завести заметку, дописать в существующую, поменять статус, найти нужное. Это не «AI-фича внутри приложения», а MCP-сервер поверх того же хранилища.

Сценарий, ради которого всё затевается:

> Работаю с Claude Code над задачей A. Находим баг, который к A не относится. Говорю: «заведи задачу, вернёмся после текущей». Агент создаёт заметку со статусом `active`, тегом репозитория, ссылкой на текущую заметку и описанием бага. Я её вижу в приложении сразу — без перезапуска, без импорта.

## 2. Принципы, от которых нельзя отступать

| Принцип | Следствие |
| --- | --- |
| **Файлы — источник правды** | Заметка — это `.md` файл на диске с YAML frontmatter. SQLite — только индекс, удаляется и перестраивается в любой момент без потери данных. |
| **Никакой системы плагинов** | Приложение для одного человека. Нужна фича — правится исходник. Никаких реестров компонентов, именованных зон лейаута, API для сторонних расширений. |
| **Никакого AI внутри приложения** | Ни автокомплита, ни инлайн-ассистента, ни API-ключей, ни Keychain. Весь интеллект приходит снаружи через MCP. Приложение об этом не знает. |
| **Vim — не опция, а база** | Режим включён по умолчанию, тестируется наравне с обычным вводом. |
| **История — это git** | Никаких ревизий в базе. Хранилище — git-репозиторий с автокоммитом. |
| **Приложение может быть закрыто** | MCP-сервер работает с хранилищем напрямую и не требует запущенного UI. |

## 4. Хранилище на диске

### 4.1. Раскладка

```
~/Notes/                          # vault, путь настраивается
├── .git/
├── .oak/
│   ├── index.sqlite               # индекс, в .gitignore
│   ├── index.sqlite-wal
│   ├── notebooks.json             # иконки и порядок ноутбуков
│   └── config.json                # настройки приложения
├── .gitignore                     # содержит .oak/index.sqlite*
├── attachments/
│   └── 2026/08/rr3k9q2x.png
├── templates/
│   ├── bug-report.md
│   └── daily.md
├── .trash/
│   └── udalyonnaya-zametka.md
├── Работа/                        # ноутбук
│   ├── Проект X/                  # вложенный ноутбук
│   │   └── refactoring-plan.md
│   └── standup-notes.md
└── Личное/
    └── pokupki.md
```

- **Ноутбук = папка.** Вложенность произвольная.
- **Заметка = файл** `<slug>.md`. Slug генерируется из заголовка при создании (транслит кириллицы, нижний регистр, дефисы, максимум 60 символов), при коллизии добавляется `-2`, `-3`. **После создания имя файла не меняется автоматически** — переименование заголовка не трогает файл. Есть отдельная команда «Переименовать файл», делающая `git mv`.
- Файлы и папки, начинающиеся с точки, игнорируются, кроме `.trash`.
- Любой `.md` файл, положенный в vault извне, подхватывается watcher'ом; отсутствующий frontmatter достраивается при первом открытии.

### 4.2. Frontmatter заметки

```yaml
---
id: 01K3QF8ZN7X2WPBV4YHMC6TDAE   # ULID, неизменяемый
title: Перерасчёт значений свойств
created: 2026-08-18T13:12:03+03:00
updated: 2026-08-18T14:40:11+03:00
status: active                     # none | active | onHold | completed | dropped
tags: [работа, armz, баг]
pinned: false
origin: agent                      # user | agent — кто создал заметку
context:                           # опционально, заполняет агент
  repo: armz-frontend
  branch: feature/recalc
  commit: 3f9a1c2
---

Текст заметки в markdown.
```

Правила:

- `id` — ULID (лексикографически сортируемый, содержит время создания). Генерируется один раз, никогда не меняется. По нему работают ссылки.
- `title` — единственный источник заголовка. **H1 в теле не является заголовком** и рендерится как обычный H1. В UI заголовок — отдельное поле над редактором.
- `created` / `updated` — ISO 8601 с таймзоной. `updated` пишется приложением при сохранении; при внешнем изменении файла берётся mtime.
- `status` — отсутствие поля эквивалентно `none`.
- `tags` — плоский список строк. Регистр сохраняется, сравнение регистронезависимое.
- Неизвестные поля frontmatter **сохраняются как есть** при перезаписи файла. Не терять чужие данные.
- Порядок ключей при записи фиксированный (как выше) — чтобы git-диффы были чистыми.

### 4.3. Корзина

Удаление = перемещение файла в `.trash/` + запись `trashedFrom: Работа/Проект X` и `trashedAt` во frontmatter. Восстановление возвращает по этому пути (если папка исчезла — в корень). «Удалить навсегда» делает `rm` + коммит.

### 4.4. Вложения

- Вставка из буфера или drag&drop → файл в `attachments/<год>/<месяц>/<8 символов base32>.<ext>`, в текст вставляется `![](attachments/2026/08/rr3k9q2x.png)`.
- **Путь всегда от корня vault**, не относительный от заметки. Приложение резолвит его само. Трейд-офф осознанный: markdown становится чуть менее переносимым в сторонние вьюверы, зато перемещение заметки между ноутбуками не ломает картинки.
- Ограничений на тип файла нет — можно прикреплять что угодно, не только картинки. Для не-картинок вставляется обычная ссылка `[filename.pdf](attachments/...)`.
- Осиротевшие вложения: команда «Найти неиспользуемые вложения», показывает список, удаляет по подтверждению. Автоматически не удаляет ничего.

### 4.5. Git

- При первом запуске vault инициализируется как git-репозиторий, если ещё не.
- **Автокоммит** дебаунсом 90 секунд после последнего изменения + принудительно при закрытии приложения и перед любой массовой операцией (удаление, перемещение нескольких заметок).
- Сообщение коммита: `notes: <N> изменено` или, если файл один, `notes: <title>`. Коммиты от агента: `agent: create "<title>"`, `agent: append "<title>"`.
- Автор коммитов настраивается в `.oak/config.json`; по умолчанию берётся глобальный git-конфиг.
- Push никуда не делается. Если пользователь сам добавит remote — его дело.
- В UI: «История заметки» = `git log --follow` по файлу, диф двух ревизий, «Восстановить эту версию» = запись старого содержимого поверх текущего (не reset, чтобы ничего не терялось).

## 5. Индекс SQLite

Файл `.oak/index.sqlite`, режим WAL (важно: с ним одновременно пишут приложение и MCP-сервер).

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

CREATE TABLE notes (
  rowid       INTEGER PRIMARY KEY,
  id          TEXT NOT NULL UNIQUE,          -- ULID
  path        TEXT NOT NULL UNIQUE,          -- относительно корня vault
  notebook    TEXT NOT NULL,                 -- '' для корня
  title       TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'none',
  pinned      INTEGER NOT NULL DEFAULT 0,
  created     INTEGER NOT NULL,              -- unix ms
  updated     INTEGER NOT NULL,
  mtime       INTEGER NOT NULL,              -- для инкрементального скана
  size        INTEGER NOT NULL,
  num_tasks   INTEGER NOT NULL DEFAULT 0,
  num_done    INTEGER NOT NULL DEFAULT 0,
  excerpt     TEXT NOT NULL DEFAULT '',      -- первые ~200 символов тела
  trashed     INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_notes_notebook ON notes(notebook);
CREATE INDEX idx_notes_updated  ON notes(updated DESC);
CREATE INDEX idx_notes_status   ON notes(status);

CREATE TABLE tags (
  name  TEXT PRIMARY KEY COLLATE NOCASE,
  color TEXT NOT NULL DEFAULT 'default'
);

CREATE TABLE note_tags (
  note_id TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  tag     TEXT NOT NULL COLLATE NOCASE,
  PRIMARY KEY (note_id, tag)
);
CREATE INDEX idx_note_tags_tag ON note_tags(tag);

CREATE TABLE links (
  src TEXT NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  dst TEXT NOT NULL,                          -- id цели; может не существовать (битая ссылка)
  PRIMARY KEY (src, dst)
);
CREATE INDEX idx_links_dst ON links(dst);     -- это и есть бэклинки

CREATE VIRTUAL TABLE notes_fts USING fts5(
  title, body,
  tokenize = 'trigram',
  content = ''                                -- contentless: тело не дублируется
);

CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

**Про токенизатор:** `trigram` вместо `porter`/`unicode61` — он даёт частичный поиск (найти «trin» внутри «string»), работает с русским и с кодом одинаково. Inkdrop перешёл на него же в 5.9.0. Цена — индекс крупнее; для десятков тысяч заметок это единицы мегабайт.

**Contentless FTS5** (`content=''`) означает, что таблица не хранит копию текста, но и не умеет отдавать его обратно — сниппеты для подсветки строим сами из файла. Если это окажется неудобно, переключить на обычную fts5 — вопрос одной миграции.

**Синхронизация индекса:**

- При старте — быстрый скан: рекурсивный обход vault, сравнение `(path, mtime, size)` с таблицей. Изменённые перечитываются, пропавшие удаляются, новые добавляются.
- В рантайме — chokidar на vault, дебаунс 200 мс, те же операции.
- `meta.schema_version` — при несовпадении с версией в коде индекс сносится и строится заново целиком. Это всегда безопасно: правда в файлах.
- Полная переиндексация 10 000 заметок должна укладываться в несколько секунд. Если нет — профилировать, а не усложнять схему.

## 6. Процессы

```
┌─────────────────────────────────────────────┐
│ Electron main                               │
│  · окна, меню, глобальные хоткеи             │
│  · VaultService (чтение/запись файлов)       │
│  · IndexService (better-sqlite3)             │
│  · GitService                                │
│  · WatcherService (chokidar)                 │
└───────────────┬─────────────────────────────┘
                │ typed IPC (contextBridge, без remote)
┌───────────────┴─────────────────────────────┐
│ Renderer (React + CM6)                      │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ MCP server — отдельный процесс, stdio        │
│  · использует те же VaultService/IndexService│
│  · работает при закрытом приложении          │
└─────────────────────────────────────────────┘
```

`VaultService` и `IndexService` живут в пакете `packages/core`, не зависят от Electron и от React, покрыты юнит-тестами. И приложение, и MCP-сервер — их клиенты. Это главное архитектурное требование: **вся работа с данными в одном месте, никакого дублирования логики между UI и агентом.**

Согласованность при одновременной записи обеспечивается WAL + короткими транзакциями. Watcher приложения увидит файл, записанный MCP-сервером, и обновит UI.

### 7.1. Раскладка

│          │                │                              │
│ Все      │ [поиск]        │ ┌──────────────────────────┐ │
│ Активные │ ─────────────  │ │ Заголовок                │ │
│          │ ▸ Заметка 1    │ │ [ноутбук] [теги] [статус]│ │
│ НОУТБУКИ │   18 авг       │ ├──────────────────────────┤ │
│ ▾ Работа │ ─────────────  │ │                          │ │

Одна тёмная тема на CSS-переменных — дубовая палитра из `theme/palette.css` (уже готова). Опционально светлый вариант и автопереключение по системной теме. Пользовательский `~/.oak/styles.css` подгружается последним и может переопределить что угодно.

## 8. Функциональные требования

Формат: требование — критерий приёмки.

### 8.1. Ноутбуки

- Дерево в сайдбаре, произвольная вложенность, разворачивание/сворачивание с запоминанием состояния.
- Счётчик заметок на ноутбуке. **Свёрнутый** показывает сумму со вложенными, **развёрнутый** — только свои.
- Создание, переименование (= `git mv` папки), удаление (заметки внутри → в корзину).
- Drag&drop заметки из списка на ноутбук перемещает файл.
- Иконка ноутбука: эмодзи или один из встроенных SVG. Хранится в `.oak/notebooks.json`.
- Порядок: ручной (drag&drop), по умолчанию алфавитный.
- **Критерий:** перемещение заметки в другой ноутбук сохраняет её `id`, все ссылки на неё продолжают работать, картинки не ломаются.

### 8.2. Теги

- Много тегов на заметку, поле с автокомплитом под заголовком, Enter фиксирует.
- Цвет тега из палитры (14 значений), хранится в индексе и в `.oak/config.json`.
- Клик по тегу в сайдбаре фильтрует список; несколько выбранных тегов работают по И.
- **Критерий:** переименование тега проходит по всем заметкам и переписывает frontmatter, одной операцией и одним коммитом.

### 8.3. Статусы

- `none` / `active` / `onHold` / `completed` / `dropped`, шоткаты `Cmd+Ctrl+1..5`.
- `completed` и `dropped` **скрыты из списка ноутбука по умолчанию**, доступны через отдельные пункты сайдбара.
- Псевдо-ноутбук «Активные» в сайдбаре — все заметки со статусом `active` и `onHold` из всех ноутбуков, отсортированные по дате изменения. Это главный экран рабочего дня.
- **Критерий:** смена статуса заметки мгновенно убирает её из текущего списка, если она перестала подходить под фильтр, без перерисовки всего списка.

### 8.4. Список заметок

- Сортировка: заголовок / создано / изменено, по возрастанию и убыванию. Запоминается.
- Закреплённые всегда сверху, отдельной группой.
- В строке: заголовок, дата, 2 строки текста, теги, индикатор статуса, прогресс чеклиста (`3/7`), если в заметке есть задачи.
- Мультивыбор `Cmd`+клик и `Shift`+клик, счётчик выбранных.
- Массовые: в корзину, переместить, дублировать, закрепить, сменить статус, добавить тег.
- Клавиши в фокусе списка: `j`/`k` или стрелки — навигация, `m` — переместить, `p` — закрепить, `Cmd+D` — дублировать, `Cmd+Backspace` — в корзину, `Enter` — фокус в редактор.
- Виртуализация списка (10 000 заметок должны скроллиться без лагов).

### 8.5. Поиск

Одно поле, два режима: **глобальный поиск** и **фильтр по текущему ноутбуку**. Переключение иконкой и `Cmd+Shift+Alt+F`.

Язык запросов:

| Синтаксис | Значение |
| --- | --- |
| `слово` | полнотекстовый поиск по заголовку и телу |
| `"точная фраза"` | фраза целиком |
| `book:Работа` | в ноутбуке (по имени, с вложенными) |
| `tag:баг` | с тегом |
| `status:active` | со статусом |
| `title:перерасчёт` | только в заголовке |
| `body:hsl` | только в теле |
| `is:pinned` | закреплённые |
| `has:task` | содержит незакрытые чекбоксы |
| `-tag:черновик` | отрицание (работает и с фразами: `-"не это"`) |
| пробел между условиями | И |

- Квалификаторы комбинируются: `перерасчёт tag:работа -status:completed`.
- Запрос только из отрицаний — ошибка с понятным сообщением (как в Inkdrop; технически FTS так не умеет).
- Совпадения подсвечиваются в открытой заметке.
- `Cmd+Shift+F` — фокус в поиск, `Esc` — сброс.
- **Сохранённые запросы**: закрепить текущий запрос в сайдбар под своим именем. Этого нет в Inkdrop, а нужно — «мои баги», «на этой неделе».

### 8.6. Редактор

CM6 со следующим набором:

- `@codemirror/lang-markdown` с GFM-расширениями Lezer (таблицы, чеклисты, зачёркивание, автоссылки).
- Подсветка кода внутри fenced-блоков через `@codemirror/language-data` (ленивая загрузка языков).
- `@replit/codemirror-vim` — **включён по умолчанию**, отключается в настройках. `:w`, `:q`, `:e` привязать к командам приложения.
- Мультикурсор, `Cmd+D` на выделении (следующее вхождение), move/copy line, join, sort lines.
- Find & replace внутри заметки с regex и учётом регистра.
- Умное продолжение списков по Enter: маркеры, нумерация с автоинкрементом, чекбоксы; двойной Enter выходит из списка; Tab/Shift+Tab меняют уровень.
- Работа с таблицами: Tab переходит по ячейкам, Enter в последней строке добавляет новую, при вводе выравнивание не ломается (переформатирование по требованию, командой, а не на каждый символ).
- Автокомплит: `[[` — по заголовкам заметок, вставляет ссылку; `:` — эмодзи; внутри блока кода — ключевые слова языка.
- Слэш-команды `/` в начале строки: таблица, блок кода, чеклист, дата, alert-блок, вставка шаблона.
- Плавающий тулбар над выделением: жирный, курсив, код, ссылка, зачёркивание.
- Панель форматирования сверху — отключаемая, по умолчанию скрыта.
- Тогглы: номера строк, перенос строк, ограничение ширины колонки текста.
- Вставка URL при выделенном тексте оборачивает его в ссылку.
- **Критерий:** vim-режим не конфликтует ни с одним шоткатом приложения; `Esc` в insert-режиме уходит в normal, а не сбрасывает поиск.

### 8.7. Markdown

Поддерживается: GFM целиком, сноски `[^1]`, GitHub-alerts (`> [!NOTE]` и остальные четыре), `<sub>`/`<sup>`/`<kbd>`, `==выделение==`, скрытие через HTML-комментарии, атрибуты блока кода (` ```ts title="src/x.ts" `), цветовые свотчи (`#c4a484` в бэктиках → квадратик цвета), KaTeX, mermaid.

Эмбеды YouTube/твитов — **не делаем** (ты сам засомневался; ссылка справляется).

### 8.8. Превью

- Пайплайн: `unified` → `remark-parse` → `remark-gfm` → `remark-math` → `remark-rehype` → `rehype-katex` → `hast-util-to-jsx-runtime` → React.
- Три режима: только редактор / только превью / рядом. `Cmd+E` переключает редактор↔превью, `Cmd+P` включает режим «рядом».
- Синхронный скролл в режиме «рядом», по позиции строки исходника (не по проценту).
- Клик по чекбоксу в превью правит исходник в редакторе.
- Блоки кода в превью подсвечиваются **тем же** highlighter'ом, что и редактор — один набор `--syntax-*` переменных на оба.
- Mermaid с pan/zoom.

### 8.9. Ссылки между заметками

- Формат: `[Заголовок](oak://note/<ULID>)`. Рендерится актуальным заголовком целевой заметки, а не тем, что записан в тексте.
- `[[` в редакторе — автокомплит по заголовкам, вставляет ссылку в этом формате.
- «Скопировать ссылку на заметку» из списка и из редактора.
- Клик по ссылке на несуществующую заметку предлагает её создать.
- **Бэклинки**: панель под редактором со списком заметок, ссылающихся на текущую. Запрос `SELECT src FROM links WHERE dst = ?`. В Inkdrop этого нет — здесь есть.
- Граф связей — **не делаем**. Красиво на скриншотах, бесполезно в работе.

### 8.10. Шаблоны

- Папка `templates/` в vault. Любой `.md` в ней — шаблон.
- `Cmd+T` на пустой заметке открывает пикер с фильтрацией и превью; недавно использованные сверху.
- Блок `_template` во frontmatter шаблона задаёт свойства создаваемой заметки:

```yaml
---
_template:
  title: "Баг: "
  notebook: Работа/Баги
  tags: [баг]
  status: active
---
## Что сломано

## Как воспроизвести

## Ожидаемое поведение
```

- Плейсхолдеры в теле: `{{date:YYYY-MM-DD}}`, `{{time}}`, `{{uuid}}`, `{{cursor}}` (куда поставить курсор после вставки).
- Применение шаблона **не затирает** уже проставленные теги и статус, только добавляет.

### 8.11. Клавиатура

- **Палитра команд** (`Cmd+K`): fuzzy-поиск по командам, ноутбукам, тегам и заголовкам заметок в одном списке, с префиксами (`>` команды, `#` теги, `@` ноутбуки, без префикса — заметки).
- Кеймап в `~/.oak/keymap.json`: `{ "контекст": { "клавиши": "команда" } }`, контексты — `global`, `editor`, `note-list`, `sidebar`, `modal`. Селекторы CSS, как в Inkdrop, — избыточная сложность; хватит именованных контекстов.
- Multi-stroke биндинги (`space e`, `g g`) — поддерживаются, для vim-мышечной памяти.
- Глобальный системный хоткей: показать/скрыть окно и «быстрая заметка» (новое маленькое окно, Enter сохраняет и закрывает).
- Экран «Все горячие клавиши» в настройках, с поиском.
- Навигация по истории просмотренных заметок: `Cmd+[` / `Cmd+]`, кнопки мыши 3/4, свайп тачпадом.

### 8.12. Окна

- Несколько окон приложения, каждое со своим состоянием.
- Открыть заметку в отдельном окне.
- Быстрая заметка по глобальному хоткею.
- Полноэкранный режим, размер шрифта `Cmd+`/`Cmd-`, запоминание геометрии окон между запусками.

### 8.13. Картинки

- Вставка из буфера и drag&drop.
- Ресайз через alt-текст: `![width:200px](...)`, `![w:320 h:240](...)`, `![width:50%](...)`.
- Тулбар размера при курсоре на картинке: Auto / 30% / 50% / 100%.
- Полноэкранный просмотрщик по клику, копирование и сохранение картинки.

## 9. Что явно не входит в объём

Не делать, даже если покажется, что легко:

- Любая синхронизация, аккаунты, шифрование, шаринг в веб.
- Мобильное приложение.
- Система плагинов, реестр расширений, публичный API.
- AI внутри приложения: автокомплит, инлайн-ассистент, хранение API-ключей.
- Импорт из Evernote / Apple Notes / Bear / Notion / Kindle.
- Браузерное расширение-клиппер, локальный HTTP-сервер, Alfred/Raycast.
- Граф связей, эмбеды YouTube/твитов.
- Экспорт в PDF/HTML (`Cmd+P` печать из превью закрывает вопрос).
- Windows и Linux сборки.

## 10. Риски и как их снимать

| Риск | Снятие |
| --- | --- |
| Потеря заметок из-за бага в приложении | Файлы + git с автокоммитом. Приложение физически не может потерять больше 90 секунд работы. Никогда не делать `git reset --hard`, `git clean`, force-push. |
| Гонка приложения и MCP-сервера за индекс | WAL + короткие транзакции + `busy_timeout`. Индекс в любой момент можно снести. |
| Watcher зацикливается на собственных записях | Реестр «своих» записей: путь + mtime, события по ним игнорируются в течение 2 секунд. |
| Vim-режим ломает шоткаты | E2E-тесты на конфликтные комбинации (`Cmd+D`, `Esc`, `Ctrl+F`, `:w`). |
| Проект надоедает на середине | Порядок фаз в ROADMAP.md подобран так, чтобы пользоваться можно было с конца фазы 3, а MCP заработал в фазе 4 — до того, как будет готов красивый UI. |
