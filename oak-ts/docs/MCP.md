# Oak MCP — контракт для агента

Это главная причина, по которой приложение вообще пишется. Всё остальное — редактор вокруг этого.

---

## 1. Что решаем

Работаешь с Claude Code над задачей A. По ходу дела всплывает что-то, что нельзя чинить прямо сейчас: баг в соседнем модуле, недочёт в архитектуре, «тут надо переписать, но не в этом PR». Сейчас это уходит либо в TODO-комментарий, который никто не прочитает, либо в отдельное окно Notion, куда надо переключиться и потерять контекст.

Нужно, чтобы работало так:

> — Claude, заведи задачу: в `RequestHeader` счётчик не пересчитывается после ручной правки. Вернёмся после текущей.
> — Готово, завёл «Счётчик перерасчёта не обновляется после ручной правки» в «Работа/Баги», статус active, тег armz-frontend. Ссылка проставлена на текущую задачу.

И чтобы эта заметка сразу была в приложении — без импорта, без перезапуска, и даже если приложение сейчас закрыто.

---

## 2. Архитектура

MCP-сервер — **отдельный процесс**, поднимаемый Claude Code по stdio. Он не общается с приложением: он работает с тем же vault напрямую через `packages/core`.

```
Claude Code ──stdio──> oak-mcp ──> VaultService ──> ~/Notes/*.md
                                 └> IndexService ──> .oak/index.sqlite
                                                          ↑
                            Oak.app (chokidar) ───────────┘  видит изменения,
                                                              обновляет UI
```

Из этого следует три важные вещи:

1. **Приложение может быть закрыто.** Агент всё равно пишет заметки.
2. **Никаких API-ключей.** Агент — это твой Claude Code, он уже авторизован. Приложение об AI не знает вообще ничего.
3. **Нет дублирования логики.** Валидация frontmatter, генерация ULID, обновление индекса, git-коммит — один и тот же код, что и в приложении.

Установка:

```sh
claude mcp add oak --scope user -- node /path/to/oak/packages/mcp/dist/index.js --vault ~/Notes
```

Конфликт записи с приложением снимается WAL-режимом SQLite и тем, что файлы пишутся атомарно (запись во временный файл рядом + `rename`).

## 3. Инструменты

Все возвращают JSON. Ошибки — с человекочитаемым `message` на русском или английском (единообразно, выбрать одно).

### `search_notes`

Основной способ агенту что-то найти.

```ts
{
  query: string,          // язык запросов из SPEC §8.5: 'счётчик tag:баг -status:completed'
  limit?: number,         // по умолчанию 20, максимум 100
  includeBody?: boolean   // по умолчанию false — отдаётся только excerpt
}
→ { total: number, notes: NoteSummary[] }

type NoteSummary = {
  id: string, title: string, notebook: string,
  status: Status, tags: string[], pinned: boolean,
  created: string, updated: string,   // ISO 8601
  excerpt: string,
  body?: string
}
```

### `get_note`

```ts
{ id: string }
→ { ...NoteSummary, body: string, backlinks: {id,title}[], links: {id,title}[] }
```

### `create_note`

```ts
{
  title: string,
  body?: string,
  notebook?: string,      // 'Работа/Баги'; создаётся, если нет
  tags?: string[],        // несуществующие теги создаются
  status?: Status,        // по умолчанию 'none'
  pinned?: boolean,
  linkTo?: string,        // id заметки: в конец тела добавится ссылка «Связано: [...]»,
                          // а в ту заметку — обратная ссылка
  context?: {             // пишется во frontmatter как есть
    repo?: string, branch?: string, commit?: string, file?: string
  }
}
→ { id: string, path: string, url: string }   // url = 'oak://note/<id>'
```

Заметка помечается `origin: agent` во frontmatter — чтобы в приложении было видно, что её завёл не ты.

### `update_note`

```ts
{
  id: string,
  title?: string,
  body?: string,          // полная замена тела
  append?: string,        // дописать в конец, взаимоисключающе с body
  prepend?: string,       // дописать в начало (после frontmatter)
  status?: Status,
  addTags?: string[],
  removeTags?: string[],
  pinned?: boolean,
  notebook?: string       // перемещение
}
→ { id: string, path: string }
```

`append` — самая частая операция в работе: агент по ходу дела дописывает найденное в существующую заметку задачи, не переписывая её целиком. Дописывание всегда отделяется пустой строкой.

### `set_status`

Отдельным инструментом, потому что это самая частая точечная операция и не хочется, чтобы агент ради неё звал `update_note` с риском задеть что-то ещё.

```ts
{ id: string, status: 'none'|'active'|'onHold'|'completed'|'dropped' }
→ { id: string, status: Status }
```

### `list_tasks`

Сахар над поиском, но с явной семантикой «что у меня в работе».

```ts
{
  status?: Status[],      // по умолчанию ['active','onHold']
  notebook?: string,
  tag?: string,
  limit?: number
}
→ { notes: NoteSummary[] }
```

Сортировка: закреплённые сверху, дальше по дате изменения по убыванию.

### `list_notebooks`

```ts
{}
→ { notebooks: { path: string, count: number, children: string[] }[] }
```

### `list_tags`

```ts
{}
→ { tags: { name: string, count: number, color: string }[] }
```

### `trash_note`

```ts
{ id: string }
→ { id: string, trashed: true }
```

Только в корзину. **Инструмента для необратимого удаления у агента нет и не будет** — это делается руками в приложении.

## 4. Чего агенту не дано

Осознанные ограничения, а не недоделки:

- **Удалять навсегда.** Только корзина.
- **Удалять или переименовывать ноутбуки и теги** массово. Слишком легко устроить погром одним неудачным вызовом.
- **Писать в `.oak/config.json`**, менять настройки приложения.
- **Трогать git напрямую.** Коммиты делает `packages/core` сам, по своим правилам.
- **Читать файлы вне vault.** Путь vault задан аргументом запуска, любой выход за него — ошибка.

## 5. Skill для Claude Code

Положить в `~/.claude/skills/oak-notes/SKILL.md`, чтобы агент понимал, когда и как этим пользоваться, без напоминаний в каждом промпте.

```markdown
---
name: oak-notes
description: >
  Ведение рабочих заметок и задач в Oak. Использовать, когда пользователь просит
  записать задачу, завести баг, зафиксировать находку «на потом», посмотреть что
  в работе, отметить задачу выполненной, или когда по ходу работы над кодом
  обнаружено что-то, что явно не относится к текущей задаче.
---

# Работа с заметками Oak

## Когда заводить заметку сам

Если во время работы над задачей находится проблема, которая **не относится** к
текущей задаче — сначала спроси одной фразой, заводить ли задачу. Не заводи
молча и не заводи по каждому мелкому замечанию.

## Как заводить

1. Заголовок — конкретный и самодостаточный. Не «Баг в хедере», а
   «Счётчик перерасчёта не обновляется после ручной правки значения».
2. Тело по структуре: что не так → где (файл, функция) → как воспроизвести →
   почему не чиним сейчас.
3. `notebook` — «Работа/Баги» для дефектов, «Работа/Задачи» для остального.
4. `tags` — имя репозитория обязательно.
5. `status: active`, если возвращаться скоро; `onHold`, если это «когда-нибудь».
6. `context` — repo, branch, commit, файл. Заполняй всегда, это дёшево и потом
   экономит много времени.
7. `linkTo` — id заметки текущей задачи, если она известна.

## Формат ссылок

Ссылки на заметки — `[Заголовок](oak://note/<ULID>)`. Wiki-ссылки не
поддерживаются.

## Что не делать

- Не удалять заметки без явной просьбы.
- Не менять статус на `completed` самостоятельно — это решает пользователь.
- Не переписывать тело существующей заметки целиком; дописывай через `append`.
```

## 6. Приёмка

Сценарий, который должен работать от начала до конца:

1. Приложение закрыто. В Claude Code: «заведи задачу: в парсере ломается экранирование кавычек, вернёмся позже».
2. Агент зовёт `create_note` с заголовком, телом, ноутбуком «Работа/Баги», тегом репозитория, `status: active`, заполненным `context`.
3. На диске появляется `~/Notes/Работа/Баги/lomaetsya-ekranirovanie-kavychek.md` с корректным frontmatter, индекс обновлён, git-коммит `agent: create "..."` создан.
4. Открываю приложение — заметка в списке «Активные», помечена как заведённая агентом.
5. Дописываю руками пару строк, ставлю `completed` по `Cmd+Ctrl+4` — она уходит из списка.
6. В Claude Code: «что у меня в работе?» → `list_tasks` не возвращает её.
7. `git log` показывает оба коммита: агентский и мой.
