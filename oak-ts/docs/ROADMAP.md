# Oak — фазы разработки

Порядок подобран по одному правилу: **каждая фаза должна заканчиваться чем-то, чем можно пользоваться.** Никаких «сначала полгода архитектуры».

Оценки — в вечерах (2–4 часа) при работе с Claude Code, не в человеко-днях фултайма.

---

## Фаза 0 — скелет · 1 вечер

Электрон запускается, три пустые панели, дубовая тема.

- [ ] pnpm-монорепа: `packages/core`, `packages/app`, `packages/mcp`
- [ ] electron-vite + React 19 + TypeScript strict, oxlint
- [ ] Окно с сохранением геометрии, нативное меню macOS
- [ ] Три колонки с тянущимися разделителями
- [ ] Тема из `theme/palette.css` подключена, тёмный вариант работает

**Готово, когда:** `pnpm dev` открывает окно, которое выглядит как Oak, но пустое.

---

## Фаза 1 — хранилище · 2 вечера

Ядро. Без UI, но с тестами.

- [ ] `packages/core`: `VaultService` — чтение/запись `.md` с frontmatter, атомарная запись через временный файл + rename
- [ ] Парсер/сериализатор frontmatter с сохранением неизвестных полей и фиксированным порядком ключей
- [ ] Генерация ULID, генерация slug с транслитом кириллицы, разрешение коллизий имён
- [ ] `IndexService`: схема SQLite из SPEC §5, WAL, полный скан и инкрементальный по mtime
- [ ] FTS5 trigram, парсер языка запросов → SQL
- [ ] `WatcherService` на chokidar с игнором собственных записей
- [ ] `GitService`: init, автокоммит с дебаунсом, log по файлу, показ дифа
- [ ] Юнит-тесты на всё перечисленное, включая round-trip frontmatter и парсер запросов

**Готово, когда:** тесты зелёные, а CLI-скрипт `pnpm core:scan ~/Notes` строит индекс по папке с сотней markdown-файлов и отвечает на поисковые запросы.

## Фаза 2 — редактор · 2 вечера

- [ ] CM6: `@codemirror/lang-markdown` с GFM, подсветка внутри редактора
- [ ] Подсветка кода в fenced-блоках через `language-data` с ленивой загрузкой
- [ ] `@replit/codemirror-vim`, включён по умолчанию, `:w` / `:q` привязаны
- [ ] Поле заголовка над редактором, сохранение с дебаунсом 400 мс
- [ ] Умное продолжение списков, чекбоксов, нумерации; Tab/Shift+Tab меняют уровень
- [ ] Find & replace в заметке, regex и регистр
- [ ] Тогглы: номера строк, перенос, ширина колонки
- [ ] `--syntax-*` переменные темы применены к `.tok-*`

**Готово, когда:** можно открыть файл из vault, писать в нём с вимом, и написанное оказывается на диске.

## Фаза 3 — приложение становится пригодным · 3 вечера

Здесь появляется то, ради чего всё: список, ноутбуки, статусы.

- [ ] Сайдбар: дерево ноутбуков, счётчики, разворачивание с запоминанием
- [ ] Список заметок с виртуализацией, сортировки, закреплённые сверху
- [ ] Превью текста, дата, теги, индикатор статуса, прогресс чеклиста в строке
- [ ] Статусы + шоткаты `Cmd+Ctrl+1..5`, автоскрытие completed/dropped
- [ ] Псевдо-ноутбук «Активные»
- [ ] Теги: поле с автокомплитом, цвета, фильтрация по нескольким
- [ ] Корзина: в корзину, восстановить, удалить навсегда
- [ ] Перемещение заметок drag&drop и по `m`
- [ ] Мультивыбор и массовые операции
- [ ] Клавиатура в списке: `j`/`k`, `p`, `Cmd+D`, `Cmd+Backspace`, `Enter`

**Готово, когда:** можешь неделю вести рабочие задачи в Oak и не открывать Notion. **Это точка невозврата — если после неё не бросил, проект живой.**

## Порядок, если времени мало

Если хочется получить пользу максимально быстро и рискнуть полнотой:

**0 → 1 → 4 → 2 → 3**

То есть: скелет, ядро, **сразу MCP**, потом редактор, потом UI. После фазы 4 у тебя уже работает главный сценарий — Claude Code пишет задачи в папку с markdown — а читать их первое время можно хоть в `bat`, хоть в самом Claude Code. Дальше приложение достраивается вокруг уже живого хранилища.
